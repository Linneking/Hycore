# 诊断驱动的三组TAN尾部实验：用户已授权实施

用户本轮明确授权先诊断取得初步结论、再按8000空闲GPU数量开展相关实验，不再需要逐组确认。145已取得完整匹配诊断，见[初步结论](../145_TAN_TAIL_DIAGNOSTIC_2026-11-04/report.md)。最初两张空闲时准备两个单项；正式预启动检查发现GPU0的原任务自然结束，三张全空闲、尚未启动任何本次生产任务，因此增加联合组，补齐BN/Leaky×输出bias的2×2。每卡一个新实验，不中断他人任务。

## 为什么选这三组

table的97.29%类IoU差额来自GT不存在时多误报部件48/49，而真实存在部件条件下总IoU差很小。lamp边界错误率略好但内部更差。冻结余弦读出降低成绩，因此本轮优先检验分类截距和尾部配套块；不把修改当已证修复。

公共前端保留DGCNN的STN、EdgeConv、多尺度/全局/类别融合、Conv8/BN8/Leaky与Conv9/BN9/Leaky，得到U256。dp1/dp2均无，正则关闭但保留同样采样与无图观察。

```text
TAN-R0（已完成控制）：
U256→EXP₀→M(256→128)→μ128→LOG₀→W₂_eff(128→50)→q50

TAN-BIAS-R0：
U256→EXP₀→M(256→128)→μ128→LOG₀→W₂_eff(128→50)
    →加可训练b50（全0初始）→q50

TAN-BNLEAKY-R0：
U256→EXP₀→M(256→128)→μ128→LOG₀
    →BN128→Leaky(.2)→W₂_eff(128→50)→q50

TAN-BNLEAKY-BIAS-R0：
U256→EXP₀→M(256→128)→μ128→LOG₀
    →BN128→Leaky(.2)→W₂_eff(128→50)→加b50→q50

四种配置（含已有R0）主loss均为CE(5q)/5，α=β=0。
```

BIAS只增加50个参数；两原M的_weight/_bias继续训练，原_bias不是普通输出截距。BNLEAKY只增加256个BN affine参数及running buffers，不新增随机映射；新BN的γ=1/β=0不抽RNG，但训练态BN/Leaky立即改变前向，不能说整体恒等初始化。

联合组增加306个参数及同样BN buffers，检验两块的互补或非加和作用；不是新增第三种机制。联合零bias时初始输出与单BN组一致，而非与原R0一致。最终实际启动数量仍以再次复查的完全空闲GPU数为准；0747171是此前两组准备源，尚未运行生产，实际三组冻结提交在执行记录另记。

## 固定协议与对照范围

fresh200，不从完成的R0续训；seed4780、trainval14007/test2874、自然shuffle32/drop_last、N2048/k40、eval16、RSGD .1→.001余弦200、momentum.9、WD1e-4、无总梯度裁剪、FP32、普通CE无平滑。每批一次编码，新增BN在主支一次更新；原正则U分叉/采样仍观察但不入训练图。没有teacher、额外数据或标签相关推理规则。

新v13，旧v10/v11/v12与原结果不改。共享旧模型state及构造RNG必须与R0精确相等；BIAS初始预测/分数亦精确一致。BN组共享参数相同但表示变换不同。生产guard对去除新增tail_bn/score_bias后的state hash核验原17c51802…；新增参数按原全网WD处理，不额外改变优化器分组。

先本机/服务器CPU合同，通过后在完全空闲GPU直接200轮，不做GPU短测；首完整轮核验437更新、每BN437、2874测试/50parts、初值/首输入/配对、R关闭、CE路由及模型优化器有限。记录新bias和新BN的梯度/参数更新，q作为实数分数不测球贴边。
