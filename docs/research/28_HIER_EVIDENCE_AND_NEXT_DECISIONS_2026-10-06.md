# 当前证据、表面矛盾与下一步决策

2026-10-06。回应用户对当前数据的综合判断请求。本次仅在既有缓存和已保存的逐代理使用统计上做 CPU/NumPy 只读补查，没有 forward、反向、GPU 使用、优化器更新或新主训练。

## 1. 当前判断

**已有证据支持局部祖先的深度排序；仍未证明稳定、有独立形态意义的类内软层次，也没有严格隔离 HIER 对分类和几何的净影响。**

不宜把结论压缩成“HIER有效”或“HIER整体坍缩”。训练中的 sample 祖先排序、代理自身的组织、冻结 proxy→whole 近四检索和最终分类各测量不同对象。新增补查还发现，e300 的静态合格集合扩大，引入了大量当轮未被 sample 选作祖先的边界代理，显著放大近四集中指标。

## 2. 新增核对：合格代理与实际 sample 使用集合

源数据为 V6 best99/e200/e300 的既有 `feature_cache.npz` 和各自 `summary.json`。后者的 `actual_ancestor_usage.status=observed_epoch_aggregate`，`source_epoch` 分别为 99/200/300。按 **proxy ID** 连接缓存与该轮 `sample/all_draws/pair`、`sample/all_draws/triple` 计数，二者之和大于零为 sample 使用集合；另核对 `active_noncollision` 集合。每个时点两种使用集合逐ID相等，数量都为188；这里不据数量相等宣称跨时点身份不变。

边界定义为缓存 proxy 的 FP64 欧氏半径 `r>=.99899`。在这三个时点，使用代理均合格且非边界，未发现使用的非合格代理；e300 的297个额外合格代理恰为合格边界集合，并未出现在该轮 sample 祖先使用集合中。

| 权重 / 使用统计轮次 | 静态合格代理 | 当轮 sample 使用代理 | 使用集合近四覆盖 ID | 使用集合最大重复近四 | 使用集合低半径1%槽位 | 使用集合方向近四覆盖 ID |
|---|---:|---:|---:|---:|---:|---:|
| best99 / 99 | 188 | 188 | 30 | 94/188 | 99.87% | 328 |
| e200 / 200 | 188 | 188 | 39 | 56/188 | 96.28% | 173 |
| e300 / 300 | 485 | 188 | 27 | 92/188 | 90.16% | 163 |

e300 同一组 dresser ID `2883,6009,7985,9123` 的373次重复可精确拆为：

- **92/188**：当轮 sample 使用代理；它们的近四合计覆盖27个 ID。
- **281/297**：当轮 sample 未使用的合格边界代理；它们的近四合计仅覆盖6个 ID，99.75%的槽位来自全池低半径1%。

因此，按“实际 sample 使用集合的最大重复近四比例”，best99约50.0%，e200约29.8%，e300约48.9%。**不能再据373/485对94/188断言末期实际 sample 使用代理发生同等幅度的退化。** 但实际使用集合仍高度偏向低半径候选，且方向检索覆盖328→173→163；不能反过来宣称问题已经消失。

这里以历史训练使用集合筛选同轮 clean-eval 缓存检索，**缓存近四不是训练时真正的后代或 pair/triple 端点**。它也不能证明297个代理过去从未使用、没有参与 proxy 目标或完全没有作用。使用统计为单轮，不能与[22](22_V5_V6_RESULTS_AND_STRUCTURE_2026-10-04.md)后40轮合并的使用频次混为一组。

派生数字见[actual_usage_subset.json](artifacts/hier_whole_diagnosis_2026-10-06/actual_usage_subset.json)。未提交原始向量、全日志、权重或私有路径。

## 3. 看起来矛盾的表现为何可以同时成立

| 表现 | 数据支持的解释 | 不能推出的结论 |
|---|---|---|
| 合格代理188→485，实际 sample 使用仍188 | 合格仅指 proxy 图互惠候选充分；新增297个边界代理未成为该轮 sample 祖先 | 合格率提升等于结构更丰富，或所有新增代理均无用 |
| 很多代理近四相同，实际祖先排序却合理 | 近四是全局 proxy→whole 检索；祖先由局部 triplet 的 hard-Gumbel 路径选择。后40轮实际 sample pair 比 triple 深98.17%，两者均浅于端点 | 最近四是训练后代；局部深度正确就有全局组合树 |
| 全体 whole 深度接近B64，dresser却内移且角向更宽 | 全局统计掩盖逐类变化。dresser仅180/8856个实例；e300深度3.558、夹角18.76°，B64last为4.568、2.97° | 所有类统一内移或统一坍缩 |
| 全局类内角度变小，个别类角度变大 | 全类pair池化受类样本数平方影响；V6 e300 bathtub夹角2.00°，B64last2.46°，dresser却相反 | 一项总体中位数代表全部40类，或更紧必然更好 |
| dresser分类改善，但末期 dresser 几何异常 | V5→V6 dresser test改善来自各自验证最佳模型，V6为e99；异常几何主要描述e300 | 末期几何引起了e99 test改善 |
| validation略升而test下降 | V6比V5多对3个val样本、少对22个test样本；单种子且同时改self-k和cosine周期 | self-k修复必然伤害分类，或V6有稳定泛化收益 |
| BN组别显著移动几何，分类基本不变 | 类别判别可容忍这些几何移动；inter关系可能更敏感，应直接检查关系而非只看OA | BN已经被证明是当前HIER失败的训练原因 |

还有一个真正需要定位的缺口：**sample 与 proxy 两项并未体现相同程度的层次组织**。后40轮实际 proxy pair 祖先仅10.18%严格浅于全部端点，55.58%深于最浅端点，34.24%与最浅端点同深；proxy triple 相应61.15%浅、38.42%深、0.43%相等。相等和反向必须分开。原HIER hinge直接约束的是到祖先的距离次序，并不直接约束这些原点深度条件；该结果不是复现错误的充分证据，但代理组织是否满足我们希望的更高层结构仍需检验。这些数值也不是全局树或形态真值检验。

## 4. 对 inter 构想的直接含义

1. **冻结检索的径向偏置已被定位。** [27](27_HIER_WHOLE_RADIAL_RETRIEVAL_DIAGNOSIS_2026-10-06.md)固定方向/代理的控制表明，统一 whole 半径使e300合格代理近四覆盖28→190；仅统一proxy半径为30。删除极低半径样本只让新热点接替。这里解释的是检索，尚未解释训练中哪个目标使特定whole变浅。
2. **类别紧凑与类内形态层次不能互相替代。** 原HyCoRe本身已有紧凑方向，加入HIER后的类内邻居明显重排；没有独立形态信号，无法判定重排的质量。现有训练抽到的j约93.6%跨类，32类×2主要保住类别覆盖，类内细粒度关系并未获得充分直接验证。
3. **HIER仍适合工程上的优先试验，但不是经当前数据验证的即插即用效果。** 暂无足够证据停止这条路线，也没有依据直接扩展epoch/K/P、增加权重或宣称已发现形态祖先。
4. **B32/B64不是同协议B0。** 9840 vs8856训练实例，shuffle vsbalanced，307/153 vs200更新/轮，best-test vsbest-val均有差异。几何同ID对齐有用，却不能隔离目标的因果影响。

## 5. 建议的执行顺序与分支条件

### 第一优先：小规模机制与关系质量诊断

在e20/best99/e200/e300固定少量balanced64计划和热点/普通dresser、bathtub等实例，分解CE、intra、Rsample的有符号径向/角向作用，同时测共享参数梯度。Rproxy不直接作用whole，只在代理侧分解。先固定triplet和祖先身份看直接hinge，再单独重放Gumbel看完整选择；跨增强/BN重分组的改变须与相同输入重复Gumbel的随机基线相比。额外诊断恢复BN/RNG，不改生产权重。

若需验证实际更新方向，可在完整模型/optimizer副本上配对做极少量base vsbase+Rsample一步比较，保留动量、LR、裁剪和投影，测同一eval输入的更新后深度。它只解释即时作用，不能独立证明长期训练原因。

同时固定同类样本对，比较原关系与半径控制关系的跨增强稳定性、独立归一化形状距离及事先选定的盲评。同类标签和冻结教师自蒸馏不充当形态真值。点云距离也有姿态、密度等局限，应与定性形态审查共同判断。

### 第二优先：同协议balanced64 B0因果对照

从V6 e20完整状态分叉，保留数据划分、抽样、global64/local32 BN、每轮200步、300轮cosine、CE/intra及优化器动量，只关闭HIER权重及proxy更新。先验证恢复与配对的短窗口，再决定完整训练。

V6原resume要求config全等，需要明确版本化分叉入口，不能直接绕过校验或只加载net。常规仅保存best/last与每20轮存档；若旧e21参数/BN未保留，只能核对其日志，不能宣称e21参数重现。严格复用旧H20需重放至已有e40存档验收；否则两个新分支共同从e20恢复，旧曲线为历史参照。

验证选模、固定结构观察轮次，官方test仅最终选定模型一次。主要结构终点用旋转不变的whole/part几何和独立形态关系；B0没有训练祖先proxy，不直接拿H20代理检索未对齐的B0坐标。

### 第三优先：只修被证实的一处

- 若径向控制后的关系更稳定、独立形态一致性更高，再短测“只改mining，loss仍用原whole”。
- 若冻结whole后的代理分项检查显示proxy目标破坏sample使用集合的组织，再讨论仅代理的参数化/投影修正。
- 若同协议B0也发生同样变化，优先调查共同基础协议；若仅H20稳定出现增量变化，再归因于inter目标。
- 分类和形态分别报告；若有单种子正面增量，再做多种子确认，不提前投入大矩阵。

暂不直接冻结BN、改SyncBN、给whole统一半径或照搬2.3cap，也不同时调整CE、lambda和采样。完整可审阅配置已更新至[04_NEXT_EXPERIMENT_PLAN.md](04_NEXT_EXPERIMENT_PLAN.md)。**本次未启动任何上述新实验。**
