## 固定评估

复测入口为`docs/research/diagnostics/fixed_hycore_checkpoint_eval_v1.py`，初始代码提交cb83192。在原有PointMLP/pointnet2、PyTorch/Geoopt环境中运行：

```bash
python docs/research/diagnostics/fixed_hycore_checkpoint_eval_v1.py \
  --repo <repository> --spec <private-fixed-checkpoint-spec.json> \
  --out <new-private-output-directory> --gpu <completely-idle-physical-index> \
  --max-seconds 900
```

spec含data_dir、expected_split_sha256和models列表。每个模型显式列name/version/checkpoint/expected_epoch/eval_batch_size。仅支持此次已核对的original、v7、v8。原版expected_epoch229、batch16；V7为187/batch32；V8主模型221/batch32；B64为132/batch32；B0-32-C01为249/batch32。轮次在运行前固定，不按复测分数挑选。

GPU先核对空闲并固定UUID，模型分配前再检查一次。CPU载入显式用户权重，V8先配置最终cap/hook再装载；原版/V7不添加V8映射。读取checkpoint自身net，不用其他轮次的best_net替换。原版输入与现代输入均为首1024、无增强/part、eval BN、FP32、无voting；两机test/val输入哈希一致。

原版的modern984诊断曾参加其完整9840训练，因此输出标记为in_sample_modern984_diagnostic；不可改名为held-out validation。V7/V8的984才是真正未用于梯度更新的留出验证。

只读验收包括：源checkpoint SHA不变、模型和BN state hash不变、没有梯度buffer、backward/optimizer调用均0。两个manifest都必须completed，失败或部分结果不能进入汇总。本轮五份结果的val/诊断和test分别完整984/2468；四组现代成绩与已有记录匹配，源best SHA和final_test记录匹配。
