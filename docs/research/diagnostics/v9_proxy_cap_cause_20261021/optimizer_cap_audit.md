# V9代理贴cap：映射与AdamW审查

2026-10-21。范围：只读本地生产源码、57/69既有证据，另做CPU映射导数与观察器测试；本审查没有训练、GPU、服务器操作或修改生产路径。新的短程训练诊断由独立runner负责，本文件不把其未完成结果写成结论。

## 结论及证据等级

1. **已由源码确认：初始化是“平均约4.14深”，不是512个代理严格同深4.14。** V9直接导入V8的HIERLoss（`inter_hierarchy_MN40/hier_proxy_scratch_v9/train.py:29,324`）。其raw参数是`N(0,I)/sqrt(256)*2.3*.9`（`hier_proxy_scratch_v8/hier_loss.py:30–32`）。本次CPU重放seed22得到raw模长最小/中位/最大1.823132/2.068640/2.285371，深度中位4.137280，初始越cap数0。因此最外侧代理离2.3仅0.014629，中位代理离cap0.231360。这只解释有限安全余量，不能解释所有代理最终越界。

2. **已由源码和CPU导数确认：cap只截断前向，不约束保存参数，越界后几乎关闭raw径向反馈。** `hier_proxy_scratch_v8/geometry.py:45–51`先把raw切向量裁至2.3，再expmap，再GS；`hier_proxy_scratch_v8/hier_loss.py:43–50`的`project_after_step`只测量，不投影参数和Adam状态。把whole统一至4.6只改变whole分支，并未改变这个代理机制。

3. **数学事实，不依赖训练推断：当前梯度几乎切向，不保证Adam更新切向，更不保证离散一步不增模。** Adam的历史一阶矩和逐坐标预条件均可产生一阶外移；完全切向的有限欧氏步也有二阶增模。weight decay本身朝内。

4. **已有直接干预证据来自V8，尚不可冒充V9因果结论。** 57在早期越界V8代理的相同当前梯度、相同v和计数下，去掉历史m的当前径向分量，可使平均增模由正转负；V9仅有69的稀疏保存轨迹。本次提供的逐真实步观察器会分开记录上述项。

5. **还原whole球壳、GS、优化器名字，不等于还原三份图像HIER参考权重的实际优化协议。** 57记录CUB/Cars/SOP权重实际为FP16、eps1e−4；V9是FP32、eps1e−8，且代理维数、LR、步数、batch及方向分布不同。官方FP32分支本来就用eps1e−8，不能称其实现错误。SOP使用eps1e−4仍497/512越cap，已经反证“whole同壳＋原版设置必然获得内层代理”。

## 映射：壳内正常径向响应，壳外骤减约六个数量级

记raw代理为w、r=||w||、u=w/r、cap R=2.3。忽略稳定项时，壳外前向只依赖u：

\[
v=Ru,\qquad p=f(R)u,\qquad
J_{w\to p}=\frac{f(R)}r(I-uu^\top),
\]

其中`f(t)=tanh(sqrt(c)t)/sqrt(c)`，c=.1。这个Jacobian消去径向向量，保留角向响应。实际源码没有detach norm，但分母用r+ε，ε=1e−5，因此`||v||=Rr/(r+ε)`，径向导数为`Rε/(r+ε)^2`，非严格零。

GS位于expmap输出之后（`hier_proxy_scratch_v8/geometry.py:28–38,51`），只把每个代理的球坐标梯度乘一个正标量`(1-c||p||²)^2/4`，自身不会把一个方向旋转为另一个方向；cap前后的方向选择性来自映射Jacobian。GS会影响送入Adam的绝对尺度及其与eps的相对关系，不能据此推断实际步长按相同比例缩小。

本次CPU读取同一生产映射，以float64输入直接反传径向/正交角向单位上游梯度（含GS）：

| raw模长 | 映射深度 | 径向增益 | 角向增益 | 径向/角向 |
|---:|---:|---:|---:|---:|
|2.07000|4.140000|7.5076e−2|9.8437e−2|.7627|
|2.29998|4.599960|5.7822e−2|8.0483e−2|.7184|
|2.30002|4.599980|2.5139e−7|8.0482e−2|3.1236e−6|
|6.88500|4.599993|2.8055e−8|2.6886e−2|1.0435e−6|

这说明一旦跨过cap，即便球坐标层面的HIER目标希望代理回到内部，传回raw模长的恢复作用也被压得极弱；角向学习仍可继续。上述数值是映射条件导数，未测HIER特定batch的球坐标上游梯度，不能单独判定首次越界的驱动力。

## AdamW：必须分清g、m、实际位移

V9实际代理优化器是AdamW，LR .01→.0005、β=(.9,.999)、eps1e−8、WD .01、不裁代理梯度，300轮cosine（`hier_proxy_scratch_v9/train.py:117–120,328–330`）。训练在反传并同步代理梯度后调用实际AdamW，再调用无操作的`project_after_step`（同文件`:478–482,489–501`）。模型梯度裁剪不作用于代理（`:489–493`）。

\[
m'=\beta_1m+(1-\beta_1)g,\quad
v'=\beta_2v+(1-\beta_2)g^2,\quad
\Delta w=-\eta\lambda w-
\eta\frac{m'/(1-\beta_1^t)}{\sqrt{v'/(1-\beta_2^t)}+\epsilon}.
\]

分式逐坐标计算。`g·u<0`才表示当前损失在普通梯度下降意义上想向外；`g·u≈0`只表示当前raw梯度没有显著直接径向分量。

- **逐坐标预条件：** 即便`g·u=0`，通常也没有`(g/(sqrt(vhat)+eps))·u=0`。例：w=(3,4)、g=(4,−3)，内积0；fresh Adam每坐标接近符号步，LR.1时Δ≈(−.1,+.1)，与u=(.6,.8)的内积+.02，产生一阶外移。已有测试及新观察器均在CPU验证。
- **历史方向滞后：** 切向梯度是相对于当时w定义。一次切向SGD后w'=w−ηg，有`g·w'=−η||g||²`；旧m在新方向上可具有负径向分量，继续减去它就会向外。保持m/v在欧氏坐标累积，不会自动做几何向量运输。
- **有限角向步：** 令a=u·Δw，则`||w+Δw||−r = a + E`，E≥0；平方恒等式是`||w+Δw||²−r²=2ra+||Δw||²`。a=0时模长仍增加，但大小要实测，不能把所有外漂归给二阶项。
- **WD朝内：** 一阶贡献严格为`−ηλr`。初期r≈2.07时约−2.07e−4/步。它可能被其他项超过；不能把WD写成贴壳的外推力。

fresh Adam在eps足够小时即使g很小，也可接近每坐标η的步幅；256维、η=.01的向量尺度约.16。这是总步长尺度，不是径向增量，也不说明初始第一步必然越cap。整体缩小HIER权重或GS尺度不能保证Adam位移同比缩小，因为m与sqrt(v)会一起变化；eps不可忽略时此不变性失效。

## 为短程真实训练提供的观测器

[optimizer_step_audit.py](optimizer_step_audit.py)只读取代理参数、梯度、Adam状态，不追加前向、反传、随机采样或优化步：

```python
before = before_step(proxy.tangent_proxies, proxy_optimizer)  # sync之后
proxy_optimizer.step()                                      # 唯一真实更新
report, snapshot = after_step(before, proxy.tangent_proxies,
                              proxy_optimizer,
                              include_snapshot=sparse_selected_step)
per_proxy = report.pop('_per_proxy')  # 单独序列化512维数组；其余可写JSON
```

它用同一个实际更新后的v'分母，把Adam步线性拆为：历史m径向、历史m切向、当前g径向、当前g切向、WD。这样“切向m/g经过预条件后的径向位移”与“原本径向m/g的作用”分开；这些是同一步的代数归因，不是彼此独立的因果消融。记录全部和更新前cap内/外两组、首次越界/返回数、真实位移、有限步余量、预测与真实参数误差。稀疏私有快照同时保存p/g/m/v前态和p/m/v后态，可CPU做配对反事实。

[2项新CPU测试](test_optimizer_step_audit.py)通过：24次真实FP32 AdamW连续步的最坏单坐标预测误差6.23e−8；m/v与step重建、平方模长恒等式、观测器不修改参数/梯度/优化器状态均通过。建议GPU现场容差2e−6并记录实际最大误差，超过时先拒绝解释分项。现有[9项数学测试](../v8_cap_mechanism/test_optimizer_math.py)已覆盖切向SGD有限增模、Adam切向梯度外移、标量梯度缩放不等于Adam步缩放等事实；57记录其历史通过，本次未重复全部运行。
