# V8全系统审查复现说明

此目录为匿名公开结果。完整模型、训练缓存、点云、对象身份、优化器状态和日志不在此目录，也不进Git。报告中的数值对应固定的本次运行；不要换成其他训练后仍沿用本报告的结论文字。

## 1. 冻结导出与系统审查

在具备原有PointMLP/pointnet2、PyTorch和Geoopt运行时的项目根目录执行。每次指定全新输出目录；GPU导出会检查完全空闲的物理卡。三个run分别执行，B64和B0没有代理。

```bash
python -m tools.hier_postrun_audit run \
  --run-dir <completed-V8-run-arm> --name V8-HIER64-K20-W0 \
  --out-dir <new-V8-audit> --extract --gpu <idle-physical-index> \
  --data-dir <ModelNet40-hdf5> --population full \
  --epochs initialization,1,5,20,40,99,100,160,200,240,best,last \
  --max-checkpoints 12 --max-seconds 7200 --batch-size 32 --seed 22 --with-pointclouds

python -m tools.hier_postrun_audit system \
  --artifact-dir <completed-V7-audit> \
  --artifact-dir <completed-V8-audit> --artifact-dir <completed-V8-B64-audit> \
  --out-dir <new-system-audit> \
  --mechanism-epochs 100,200,best,last --structure-epochs 100,200,best,last \
  --query-count 64 --noise-repeats 8 --shape-points 64 --shape-per-class 8 \
  --bootstrap 200 --mechanism-seconds 1800 --structure-seconds 1800 --seed 22
```

best/last按实际checkpoint轮次去重，不能给并不存在的轮次造数据。V8识别来源格式及配置，显式采用c≈.1、forward tangent cap2.3、官方epsilon和一次metric hook；先配置最终mu的cap/hook再装载模型。只导出训练集clean first1024/eval BN，不能改成测试集。跨机器移动缓存时要更新诊断副本的路径并保留源SHA，不要伪造丢失的optimizer/checkpoint能力。

## 2. 方向、生产算子与编码器梯度

方向演化用`diagnostics/hier_directional_evolution_v2.py`，从每个snapshot显式读取proxy mapping；不再把V8参数当作V7 c=1映射。生产FP32反向近邻由`diagnostics/hier_v8_production_retrieval_v1.py`核对。两个脚本的`--help`给出spec要求。原版几何与随机方向控制复用`hier_original_vs_v7_geometry_v1.py`、`hier_original_random_directions_v1.py`，完整身份数组仅存私有目录。

```bash
python -m tools.hier_postrun_audit backbone \
  --snapshot-spec <V8-audit>/feature_exports/snapshot_spec.json \
  --epoch 300 --out-dir <new-backbone-probe> \
  --data-dir <ModelNet40-hdf5> --gpu <idle-physical-index> \
  --microbatch-size 16 --max-seconds 600 --seed 22
```

e200、best e221、last e300分别运行。沿用64对象的全局损失与two-pass feature-adjoint/VJP，检查特征重放、RNG与只读状态。进程刚退出时GPU利用率可能短暂滞留；应重新确认空闲、换新输出目录重试，而不是绕过检查。失败记录不能进入成功证据。

实际训练祖先数量从300轮日志读取；冻结机制64查询×8噪声只用于条件响应；proxy→whole NN4始终使用完整8856候选池。三者必须分别解释。
