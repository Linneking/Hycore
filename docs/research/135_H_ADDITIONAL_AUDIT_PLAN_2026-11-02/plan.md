# 现有生产期间的补充审查计划

2026-11-02。用户询问还有哪些可进行的审查。本文件为待审阅计划，没有实施下面的新拟合、参数更新或生产训练。已有S5-R0/S5-R继续原200轮预算。

目的：把“物类出现少”“物体内部少数部件贡献弱”“参数更新被抵消”分开，并用已有日志解释正则的阶段性影响。优先复用134的缓存与检查点，在CPU小规模执行。

## 1. 类内部件贡献是否不足：最高优先级

134提高物类出现概率后恢复bag，但rocket43与motorbike31/33/34仍大多零召回。类别均衡不改变单个物体内的部件点数比例，因此下一项可检验因素是类内部件监督。

固定尺度5、原始μ128、最后M起点、原RSGD/学习率/4000更新预算、相同16类固定池和点批次：

|物类先验|原点均值监督|类内部件加权|
|---|---|---|
|自然先验|复用N5|仅新增NW5|
|16类等概率|复用U5|仅新增UW5|

权重对所有物类采用统一规则，不只给测试困难部件加权。由拟合池标签统计每类各部件频率，平方根逆频率、最大原始权重5；在每物类拟合池内把点权重均值归一为1。这样保持当前池中的类别期望总权重，控制主要变量为类内部件贡献，而不是同时提高某个物类总权重。缺失部件不凭检查集补权重。

诊断权重只由固定拟合池得到；若以后用于完整训练，改用完整训练标签统计和对应归一化，必须重新记录。类别加权不能变成按检查集低分类手工加权。

加权损失显式计算`mean_points(w[y] * CE(5z,y,reduction='none')) / 5`，保留原点数分母。不能直接使用PyTorch带weight的默认mean（分母为本批权重总和），避免额外的随机归一化变化。类内平均权重1只匹配期望总权重，不保证梯度范数相同。

先列拟合/检查池的每部件正例点数。拟合池无正例的部件标为“本对照不可检验”，不使用极端逆频权重，也不以它未恢复否定加权方案。

保持原批次与随机流，先用全1权重核对新路径能复现原N5/U5。优先检查50部件recall、precision、IoU、margin、正常类代价；重点motorbike31/33/34、rocket43，cap/mug为对照。小类恢复伴随大量误报时，不认定为成功。

判读：NW5改善支持类内部件监督贡献不足；主要UW5改善支持物类与部件两级不均衡交互；均失败仅约束当前缓存、起点、权重规则和预算，不证明特征无信息。该诊断不能替代全16类测试成绩。

## 2. 有梯度为何没有改善：原始参数更新分解

使用缓存中的同批μ、标签、原最后M和原优化器状态，对每个困难部件区分真值为该部件的点、其余点对参数梯度的贡献，并拆出历史动量、权重衰减。

当前M的_weight和_bias为普通欧氏Parameter（over_param=False），并非直接训练的球点；本设置的RSGD在这两个原始参数上的一步更新可按实际实现分解。必须保留完整参数顺序和独立优化器副本，重构更新后与真实opt.step逐坐标核对。

输出包括各项更新的方向和量级，以及更新前后正确部件相对主要竞争部件的margin。不能只以范数大/小判断某项“压制”了学习。参数更新可以线性分解，margin的非线性变化不能直接按同样比例分摊；需要逐项局部反事实验证。

若衰减/旧动量占主导，下一候选是匹配的头部优化设置；若其余点反向贡献占主导，优先监督分配；若真实更新能持续改善margin但尚未翻转，关注预算与收敛。这些均限冻结最后M，不直接解释生产中整个backbone。

## 3. 正则分项的训练轨迹：先审现有日志

现有geometry日志已有CE、加权contr、加权hier在共享节点/参数上的范数、径向/切向统计及参数更新，可按训练阶段、批次类别组成和部件出现次数分组，检查哪一项在困难类别出现时尤其突出。

已核对monitoring.py：日志不保存完整梯度向量，也没有梯度余弦。因此仅凭已有日志不能重建CE/R夹角或宣布方向冲突；径向正负摘要也不等于实际margin改变。包含bag的批次仍有其他物体，整批梯度不能归因于bag。

该审查只筛选正则分项与困难类失效的关联。需要方向性因果时，再用CPU固定特征/检查点重放并保留完整梯度；需要长期因果时，待当前200轮完成后按133决定contrast-only/hierarchy-only完整对照，不在中期自动扩展训练矩阵。

## 资源及交付

优先顺序为1、2，3可利用现有日志并行整理。拟合缓存仅服务器CPU加载，保留μ球坐标，不增加GPU编码、不改活跃生产源。使用独立输出目录并记录提交、缓存/checkpoint hash、采样流、预算、环境及失败状态。真实缓存/参数/动量仅服务器保存。

执行时可先完成一次更新重构的快速核对，再运行两条加权拟合；CPU线程限制为1–2并观察训练数据加载速度，避免给当前生产增加明显资源竞争。

每项交付“假设—匹配控制—实际结果—仍不能解释什么”，最终仍回到原DGCNN Class目标；不把初始化问题或径向死区预设为结论。
