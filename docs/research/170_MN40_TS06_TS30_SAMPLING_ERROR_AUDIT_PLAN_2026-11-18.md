# TS06 与 TS30：训练抽样频次和逐对象错误筛查计划

状态：待用户审阅。本轮只阅读已有代码与记录、制定计划；尚未连接服务器执行本项统计、重建抽样或模型推理，不新增训练，不做梯度审查。

## 要回答的问题与检查对象

主比较为TS06（B05，SH32×307，H0）与TS30（B13，CB32×200，H0），均为seed4780、官方train9,840/test2,468、300轮。目标是列出训练对象出现频次，找到持续出现方向性预测分歧的对象，并核对分歧与类别供给、类内形态覆盖的关系。

训练集和测试集分别建表。测试对象的训练抽样次数为0，因此测试错误只能关联其所属类别的训练供给或相近形态训练对象的供给，不能把训练ID的频次直接移到测试ID上。对训练集则可直接关联同一个对象的抽样次数与训练完成后的clean/eval错误。训练时的增强视图在线错误与clean训练错误分开称呼。

核心模型集合固定为{TS06, TS30}，“两模型均错”指该集合。辅助加入TS31（CB32×300，H0）检查增加CB更新数后哪些分歧保留；若报告“三个H0均错”，集合明确为{TS06, TS30, TS31}。不把有限集合的共同错误称为全部历史模型均错。

## 1. 先做身份、文件和可复现性盘点

- 读取每条运行的正式清单、源提交、实际配置、数据指纹、训练分片顺序、best及last身份。确认HIER关闭、原基础损失/几何不变。
- 检查是否已有逐对象预测、采样摘要或缓存；只有模型权重、输入协议和样本ID均匹配时才复用。
- 建立稳定ID：`split / HDF5分片名 / 0基行号`。训练拼接索引通过各运行实际分片顺序映射到此ID，并核对标签和原始点云指纹。数据自带原始mesh名称映射且核对通过时附加原名，否则保留可追溯HDF5 ID。
- 盘点两模型共同保存的末段检查点，优先e200、e220、e240、e260、e280、e300。代码具备周期保存机制，实际文件是否齐全仍须核实；不将逐轮标量日志当作逐轮预测或权重。
- 主表比较各自历史best：TS06 e184、TS30 e262；另外比较各自e300。抽样累计量严格截止对应模型的训练时点，不能用e300的频次解释e184模型。

best测试复评应与历史OA/AA一致。按当前日志精度，TS06 best预计2,328/2,468正确，TS30 best为2,316/2,468正确，净差12个。若权重复评不匹配，先定位数据、模型装载和输入协议，停止输出错误归因。

## 2. 重建每个训练对象的抽样次数

### 理论期望先给基准，实际频次再单独统计

设类别c有n_c个训练对象，以下均为原始对象被取入训练批的次数；whole和part两次前向不计作两次抽样。

| 口径 | SH32 / TS06 | CB32×200 / TS30 |
| --- | --- | --- |
| 单轮对象呈现 | 9,824，轮内无放回，16个尾部对象丢弃 | 6,400，有放回，允许同一对象重复 |
| 单轮每类期望呈现 | 9,824×n_c/9,840 | 160 |
| 单轮每个对象期望呈现 | 9,824/9,840 ≈ .9984 | 160/n_c |
| 全300轮每对象期望呈现 | 约299.512 | 48,000/n_c |
| 各自best时每对象期望呈现 | e184约183.701 | e262为41,920/n_c |

因此CB32相对SH32会增加小类中单个对象的呈现次数，减少大类中单个对象的呈现次数。理论上全300轮供给比的分界约为n_c=160；在各自best时点，分界约为n_c=228。均为期望值，不能冒充历史实测次数。

### 重建的验收条件

- CB32：用原版本采样器、实际标签顺序，以及seed/epoch/step，CPU重建全部批次对象索引。核对已保存的采样摘要、首轮覆盖和检查点采样器状态；统计批内同一对象重复。
- SH32：按历史PyTorch版本、模型初始化后的全局CPU随机流和train/test DataLoader调用顺序重建shuffle及drop_last。核对初始化指纹、多个历史检查点CPU RNG和可用采样摘要。重建抽样索引不需要训练或重放全部增强。
- 区分“原日志直接记录”“通过历史状态验证的重建”“理论期望”三种来源。若SH精确重建未通过，不输出伪精确逐对象次数；可验证区间独立报告，无法恢复部分给出范围或标缺失。

输出每个train ID在best、e300以及早/中/晚阶段的出现次数、出现过的轮数、单轮重复、最长缺席、不同对象覆盖率、同类搭档的不同对象数。分别报告类别总供给和类内对象间频次离散程度，避免把类别少见与同类内某个对象少见混成一种情况。重复呈现同一个对象不等于增加了形态多样性。

## 3. 在同一clean输入上复评并划分对象

使用冻结模型和eval模式，固定前1,024点、原评估协议、无增强、无投票，BN状态保持冻结。记录ID、真类、预测类、正确性、真类分数差和真类排序。测试复评分数必须匹配日志；训练集用相同clean协议另行统计，不冒充历史在线增强训练OA。若原日志只有在线训练汇总OA，不据此反推或伪造逐步错误ID；已有逐步ID和预测时才另列在线结果。

| 分组 | TS06 | TS30 | 用途 |
| --- | --- | --- | --- |
| 两模型均正确 | 对 | 对 | 频次和形态的参照组 |
| SH优势组 | 对 | 错 | 定位CB相对SH损失的对象 |
| CB优势组 | 错 | 对 | 定位CB补回的对象，必须保留 |
| 两模型共同错误 | 错 | 错 | 检查共同困难对象；再分错成同类/不同类 |

训练和测试分别输出四组ID清单。每个真类同时报告SH优势数、CB优势数、净损失数及错误率差；测试集满足：

`SH OA − CB OA = (SH优势对象数 − CB优势对象数) / 2468 × 100`。

best表的净差应为12个。SH优势组本身可能远大于12，不能把该组全算作CB净损失。补充各类对OA和AA差值的贡献，区分大类对象数多与类别错误率高。

## 4. 将一次分歧与持续分歧分开

best分歧是初筛，不直接称为稳定batch敏感。用两模型共同存在的末段检查点检验同一对象：

- 有完整6对检查点时，至少5/6对保持“SH对、CB错”定义为持续SH优势候选，反向同理；6/6另标最强持续组。
- 列出每个对象在全部时点的预测轨迹、正确率和分数差；若best分歧在后续反转，标为阶段性分歧。
- 若只能取得少量共同权重，实际时点逐个列出；3–5对时需全部同向才标持续候选并注明证据较少；少于3对不赋予稳定标签，不补造逐轮预测。
- TS31用于辅助分层：TS30错而TS31恢复的对象为“增加CB步数后恢复”；TS30/31均持续错而SH持续对为优先检查候选。

持续跨检查点分歧支持该两次训练的稳定差异；单seed、不同训练入口及预算仍不能证明由batch组成单独造成，也不替代独立重复训练。

## 5. 检查频次与错误的关联

### 类别层面

逐类连接：训练对象数、理论与实际抽样供给、不同对象覆盖、测试对象数、两方向分歧数、OA/AA贡献和主要混淆去向。检查CB中被降低训练供给的类别是否贡献更多SH优势对象，并同时观察被提高供给的小类是否出现反向收益。报告原始计数和按类归一的错误率，不能只按错误对象总数排序。

用40类的供给比与错误率差做描述、相关系数和不确定性检查。单独分析类内对象频次，防止相关性仅由类别规模驱动。即使显著也只称关联，不预设频次一定解释分差。

### 训练对象层面：可直接连接同一ID

比较同一类别内四组对象的累计呈现次数、阶段分布、搭档多样性和clean预测结果。检查“CB低频对象更易成为SH优势组”是否在控制类别后仍存在；同时保留两模型都正确的低频对象和CB高频仍错对象，检验反例。必要时补充分数差，避免所有训练对象已预测正确而二值错误缺少信息。

### 测试对象层面：通过训练供给间接连接

对持续SH优势、持续CB优势、共同错误和匹配的共同正确参照对象，检索同类中相近形态的训练对象。先用独立于TS06/TS30的固定几何描述做候选筛选，再用固定下采样点云的Chamfer距离核验；不只用某一模型自己的特征定义相似性。主分析取最近5个训练对象，10个作敏感性检查；距离较远时明确缺少相近训练支持。

连接这些训练邻居各自实际呈现次数、CB/SH供给比与形态覆盖，检验“这个测试形态在CB中接触较少”是否有一致证据。测试样本自身抽样次数为0，这一步仍是局部训练覆盖的间接证据，不能写成该测试对象被少采了。

## 6. 看具体形态并交付证据

先按类别净损失和持续性排序，再展示对象本身。每组预先固定规则选代表，使用统一点云视角、多个方向，标注ID/真类/两模型预测/持续性；配上最近训练对象及频次。观察稀有子形态、形态近邻混淆、点云缺失/离群等特征。标注含糊仅作人工待核项，不凭模型分歧认定错标。

最终交付：

1. 40类训练供给与测试净损失总表，精确说明12个净正确差来自哪些类别。
2. train/test分开的逐对象预测表、频次表、四组ID清单、跨检查点持续分歧及共同错误清单。
3. 持续SH优势/CB优势对象的形态图册和训练邻居供给表，含反例。
4. 每个结论注明频次来源、checkpoint身份、稳定性证据，以及仍无法区分的训练因素。

## 执行范围

先做文件盘点和CPU采样重建；随后复用匹配缓存，缺失预测才使用一张完全空闲GPU分批只读复评。best与e300检查train/test，两模型共同末段权重重点检查test；TS31作为辅助，不遍历全部V9/V10模型。几何邻居分析优先局限在持续分歧及匹配参照对象，控制计算量。

原始权重、数据、完整逐对象输出保留服务器或本机私有目录；仓库只提交计划、脱敏汇总与必要图表。新诊断输出使用新目录，原训练结果和正在训练的任务不改。若后续关联值得验证，再单独提出保持数据供给、更新预算和增强一致的分组验证；本计划不授权任何新训练。
