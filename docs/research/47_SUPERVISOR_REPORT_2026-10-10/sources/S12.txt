# V4 经验教训与下一版诊断优先级

命名提示：本文展示名称按[统一实验命名规范](33_EXPERIMENT_NAMING_CONVENTION_2026-10-06.md)更新；原名称可查映射。文件名、运行目录、代码字段与既有结果身份保留。

历史映射：B0 → LEGACY-V4-B32-Q4x8-BN1；H3 → LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1；H5 → LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1。
三组均为 global32 的 4×8 类内队列协议，child 独立存储，每步仅 whole 更新 BN 运行统计；HIER 组先 W20，再 R20。旧简称属于运行身份，保留在代码字段与结果目录中。

日期：2026-10-03。本文供用户审查，不授权下一轮训练。

## 1. 先给出结论

V4 得到了一个值得保留的信号：在同一协议、同一 seed 下，LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1 优于 LEGACY-V4-B32-Q4x8-BN1。但 LEGACY-V4-B32-Q4x8-BN1 本身出现明显后期推理退化，因此当前不足以证明融合方法稳定有效，也不能把 LEGACY-V4-B32-Q4x8-BN1 当成原版 HyCoRe 的复现。

下一版首先恢复用户要求保留的 HyCoRe 输入处理和 BN 更新流程，核对双卡梯度与采样实现，再在固定基础协议上筛查 HIER 的 K。增加代理数、三元组重抽次数或者损失权重，均不应替代这些诊断。

## 2. 实验身份和已完成结果

- V4 训练代码：`dc417173a04d873cdf05acc62d182d275f09054b`。
- 三组均完成 200 epoch；seed=22；8856 个训练实例、984 个验证实例。
- 前 20 epoch 完全共享，LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1/LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1 在此后加入 HIER；最大验证 OA 选模型，完整训练结束后读取一次正式 test。
- 三组除 HIER 开关和 sample K 外使用同一 V4 协议。原方案见 [V4 计划](10_HIER_PROXY_V4_PLAN_2026-10-02.md)。

| 组别 | 最佳验证 OA / epoch | 验证选中模型的 test OA | 第 200 epoch 验证 OA |
|---|---:|---:|---:|
| LEGACY-V4-B32-Q4x8-BN1：CE + intra | 89.8374% / 128 | 88.3712% | 78.3537% |
| LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1：LEGACY-V4-B32-Q4x8-BN1 + HIER，sample K=3 | 90.3455% / 130 | 89.5462% | 80.5894% |
| LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1：LEGACY-V4-B32-Q4x8-BN1 + HIER，sample K=5 | 89.6341% / 72 | 88.1686% | 71.8496% |

LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1 相对 LEGACY-V4-B32-Q4x8-BN1 的 test OA 为 +1.1750 个百分点；LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1 为 −0.2026 个百分点。这是单 seed 的配对结果，不是跨 seed 的稳定性结论。最后 20 epoch 的波动也不是多 seed 方差。

历史原 HyCoRe 的 94.044% 与上述结果的训练划分、输入、BN、batch 和训练预算不同，不能用两者的差值估计 HIER 效果。

## 3. LEGACY-V4-B32-Q4x8-BN1 与原 HyCoRe 的差异必须先承认并拆开

| 项目 | 原 HyCoRe | V4 | 下一版处理 |
|---|---|---|---|
| child 对 whole 的存储影响 | child 是切片视图，采样赋值会覆写 whole 的前段 | child 独立存储，whole 不被覆写 | 恢复原行为；记录采样前后输入，不把取消覆写视为无影响修复 |
| BN 运行统计 | child 前向之后 whole 前向，两次都更新 | child 只用 batch 统计，不更新运行统计 | 恢复两次更新；保持 HyCoRe 从头训练的 BN |
| batch 组成 | 打乱训练实例，batch32，丢弃最后不足一批的实例 | 4 类 × 8 例，整轮覆盖队列 | 双卡各 16 类 × 2 例属于新的训练协议，需有 HIER 关闭对照 |
| batch 时序 | 随机实例顺序 | 按剩余 chunk 数优先排大类，整轮 batch 列表未再打乱 | 消除按类大小形成的早晚偏置，统计分段类别曝光 |
| 训练 / 验证 | 原入口使用完整官方训练集，历史评估协议不同 | 固定 10% 分层验证划分 | 保留新验证协议用于模型选择；不能宣称整套原协议复现 |
| 总预算 | 原入口默认 300 epoch | 200 epoch，每轮 281 step | 同时报告 epoch、优化 step、draw 和唯一实例数 |

源文件：原路径 `classification_ModelNet40/main_pointmlp_hycore.py`、`classification_ModelNet40/hutil.py`；V4 路径 `inter_hierarchy_MN40/hier_proxy_scratch_v4/train.py`、`sampler.py`（基础loss导入 `inter_hierarchy_MN40/hutil.py`）。

**我的 V4 修改同时改变了输入存储、BN 和 batch 协议，导致 LEGACY-V4-B32-Q4x8-BN1 失去原版基线身份。** 当时的数值测试和短 smoke 通过，只证明这些改动能够运行，不能证明改动改善了完整训练的稳定性。下一版恢复它们也不能直接证明其中任一项是退化根因；如需因果归因，要单项对照。

## 4. 退化不能仅解释为通常意义上的过拟合

对 LEGACY-V4-B32-Q4x8-BN1 原始权重、原始 BN，用 eval 模式和无增强完整 1024 点输入评估训练集：

| LEGACY-V4-B32-Q4x8-BN1 检查点 | 训练集 clean eval OA | 验证 OA |
|---|---:|---:|
| 最佳：epoch128 | 91.7344% | 89.8374% |
| 末轮：epoch200 | 81.3686% | 78.3537% |

末轮 train 模式日志 OA 为 93.3385%，但同一训练集在推理流程下只有 81.3686%。退化也发生在已经见过的训练实例上。

这个诊断同时改变了 BN 模式和输入形态：训练使用增强及随机 whole 子云，clean eval 使用完整点云。因此，现有证据不能把全部差异归因于 BN，也不能把 train 日志与 val 的差距全部归因于未见数据泛化。

下一版需要固定输入，分别检查 BN 模式；再固定 BN 模式，分别检查原 whole 处理和完整输入。常规记录 train 模式 OA、训练集 clean eval OA、验证 OA 和逐类指标。

## 5. BN 敏感，但重校并非通用修复

仅用训练集、无梯度重校 BN 后，LEGACY-V4-B32-Q4x8-BN1 末轮验证 OA 从 78.3537% 提升到 82.5203%；最佳模型却从 89.8374% 降到 87.3984%。

这证明运行统计选择影响结果，但不支持直接把重校纳入正式评估来掩盖退化。HIER 图像代码冻结预训练 BN 的运行统计，也不能直接移植给从头训练的 HyCoRe；其 BN 仿射参数仍可训练。

双卡首版采用每卡 32 例的普通 BN。DDP 的 buffer 广播不等于跨卡统计；SyncBN 会改变训练行为，应独立对照。

## 6. V4 全覆盖，但存在类别时序偏置

每轮 281 batch、8992 次 draw，唯一训练实例为 8856，覆盖率 100%；136 次额外 draw 是固定形状填充，占 1.51%。V4 中的零准确率类别不是因为实例未被使用。

第 200 epoch 的 sampler 重建显示：前 20 batch 仅出现 7 类；door 首次出现在第 161 / 281 batch，flower_pot 在第 131 / 281 batch；最后 20 batch 则恰好每类 16 次 draw。

实例覆盖充分与类别时序均匀是两件事。BN 对近期 batch 敏感，这种偏置是值得隔离的因素，但目前尚无只改变 batch 顺序的训练对照证明它造成了多少退化。

后续采样诊断必须分别报告：draw 总数、唯一实例覆盖、每类覆盖、重复率，以及类别在 epoch 前中后段的曝光。

## 7. 零准确率类别要在训练集和验证集同时检查

door 有 98 个训练实例、11 个验证实例；flower_pot 有 134 / 15。三组验证选中的模型在既有正式 test 上，两类均为 0%。flower_pot 在三组全部 200 epoch 的验证记录中均为 0%，LEGACY-V4-B32-Q4x8-BN1 最佳模型在训练集 clean eval 上也为 0%。

LEGACY-V4-B32-Q4x8-BN1 最佳到末轮，验证 bookshelf 从 91.2% 降到 3.5%，table 从 94.9% 降到 0%。这要求记录混淆和训练集逐类推理表现，不能仅看总体 OA，也不能把所有失败归因于小类样本少。

## 8. K、T 和覆盖率不能混用一个解释

| epoch21–200 的统计 | LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1 | LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1 |
|---|---:|---:|
| 合格 anchor / batch | 57.506% | 84.632% |
| sample draws / batch | 1177.73 | 1733.27 |
| 负 pair 覆盖 | 89.994% | 91.421% |
| 完整候选 triplet 覆盖 | 56.727% | 41.694% |
| draw 中同类 k 的比例 | 15.185% | 9.435% |
| pair / triple 选中同一代理的碰撞 | 12.758% | 13.804% |
| active triplet / 全部 draw | 20.490% | 19.699% |

- V4 的 4×8 batch 中有 7 个其它同类位置，优先占满 K3 / K5，j 全部同类。新全局 32×2 batch 中只有 1 个其它同类位置，关系池的含义会发生变化。
- K5 提高 anchor 覆盖，却改变同类 / 异类关系比例，也扩大了 triplet 覆盖的分母。其覆盖百分比更低，不代表实际抽取更少。
- T64 已覆盖约 90% 的负 pair；目前没有证据表明重抽次数是主要瓶颈。增加 T 不能增加互惠邻居，也不能使不合格 anchor 合格。
- 代理碰撞是两次祖先选择选到同一代理；它与重复抽到同一个 `(i,j,k)` 不同。碰撞会被 mask，所以 `1−active率` 不能当作约束满足率。
- V4 的 K 排除 self；官方 HIER 的 K 先包含 self。新 K6 / 8 / 10 不能直接按数值与旧 K3 / 5 比较。

## 9. HIER 有实际梯度作用，但低 loss 不证明层次有效

首 batch 中，加权 inter / base 的 whole 嵌入梯度范数比均值为 LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1 的 0.27884、LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1 的 0.27018；梯度 cosine 均值分别 −0.13728、−0.15527。

这里 base 包括 CE 和 intra，且仅检查每个 epoch 的首 batch、嵌入处梯度。不能把它写成“全训练期间 CE 与 HIER 必然冲突”。下一版应分别检查 CE、两个 intra 和 inter 的梯度贡献。

LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1 的 inter loss 更低，却未获得更好的推理结果。在线候选池和代理会变化，仅靠训练正则项下降不能证明软层次学得更好。分类收益与独立形态 / 语义层次证据应分别报告；不预先限制用户提出的共同祖先设想。

## 10. 忠实性不能只检查三个 hinge

V4 使用 c=1、margin / tau=0.0316227766、普通反向、无额外 whole 截断；代理为 epoch20 特征的 k-means 初始化、P256、独立 proxy K20；sample T64 / proxy T32；两项权重各 0.03，另加 warmup 和 ramp。这些都不同于 HIER 发布脚本。

保留 HIER 的代理选择和三个 hinge，不等于完整复制其优化过程。下一版必须逐项声明保留项和适配项，尤其是共享 whole 上的截断、反向处理和代理优化器。

原 HyCoRe 的标签平滑 CE 使用球内坐标作 logits，loss 尺度不能按常见无界 logits 的 CE 判断。part200–600 点与固定 FPS512 的重复 anchor 行为也继承自原版；首版保留它，不把动态 FPS 与当前 batch / BN 修复混在一起。

## 11. 下一版工作优先级

1. **基础忠实性**：恢复 part 复写及 child→whole 两次 BN 更新；验证原 intra、CE、优化器设置与关闭 HIER 的路径。
2. **双卡正确性**：全局类别划分、可微 gather、代理同步、损失归约和梯度尺度核对。
3. **训练协议**：明确每轮步数和覆盖目标，审计类别时序及 train / eval 差异。
4. **HIER 关系**：同 batch / 同特征测试 K6 / 8 / 10，按官方互惠规则跳过不足两个 j 的 anchor，分别报告覆盖与碰撞。
5. **方法收益**：稳定基础协议后比较 HIER 关闭 / 开启；再做多 seed 和独立结构验证。
