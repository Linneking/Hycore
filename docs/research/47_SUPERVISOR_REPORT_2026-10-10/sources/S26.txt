## 1. 这次比较回答什么

用户希望确认：原版 HyCoRe 与我们的 V6-B0-64 训练是否有明显差异，batch 的组织是否改变了训练，以及 whole / part 的半径、层次间隔和逐类分类表现是否随之变化。

比较三个训练身份，避免把“历史原版”和“本次源码默认复现”混为一组：

1. **ORIG-B0-32-S4780，seed4780**：用户保存的 HyCoRe 权重及日志，目标300轮；训练早期有一次续训。
2. **V6-B0-32，seed22**：直接调用原 `classification_ModelNet40/main_pointmlp_hycore.py` 的训练函数，完整9840训练、300轮、307步/轮。包装只增加被动监测及完整保存。
3. **V6-B0-64，seed22**：双卡每卡32，global64；完整9840训练、无放回全局 shuffle、153步/轮、300轮；没有 HIER / inter / proxy。

三个模型都使用 Hype_pointMLP、固定 c=1、D256、原 CE 和两项 intra。历史 `args.model=Hype_PointNet` 是入口参数名，实际源码硬编码构造的是 Hype_pointMLP，不能据这个字符串认定网络不同。

这次不能只比较两个最佳 OA 就断言 batch 有益或有害：V6-B0-64 相对于V6-B0-32 同时改变了每次更新的样本数、更新次数、flip 负配对、随机流和双卡 BN 协议。ORIG-B0-32-S4780 还增加了 seed、resume 与未完整记录的旧环境差别。

## 3. 原版与 V6-B0-64 的 batch 到底有什么不同

### 3.1 原版没有固定的4类×8或16类×2

原源码训练加载器是普通 `DataLoader(..., batch_size=32, shuffle=True, drop_last=True)`。它先随机打乱全部训练实例，再连续取32例，类别数和每类例数自然变化。没有固定类别块，没有类内有放回抽样，也没有要求某类在一批出现两次。

V6-B0-64 同样按实例全局无放回打乱，不是 V6-HIER64-K20-W20 的类别均匀抽样。全局64中的前32给 rank0，后32给 rank1；各卡也不固定类别数。因此“V6-B0-64随机训练”与“V6-HIER64-K20-W20全局32类×2”必须分开描述。

| 项目 | V6-B0-32 | V6-B0-64 |
|---|---|---|
| 训练集 | 完整9840实例 | 完整9840实例 |
| 打乱单位 | 实例 | 实例 |
| 打乱实现 | 原 Torch RandomSampler / DataLoader | 私有 Python RNG，`random.Random(seed+epoch).shuffle` |
| 类别约束 | 无固定类数或类内样本数 | 无固定类数或类内样本数 |
| 每次模型更新 | 一个32例 batch | 两个 local32 合成 global64 |
| 每轮完整 batch | 307 | 153 |
| 每轮唯一实例 | 9824 | 9792 |
| 每轮随机丢尾 | 16 | 48 |
| 每轮唯一覆盖率 | 99.837398% | 99.512195% |
| 300轮实际优化更新 | 92100 | 45900 |
| 每个 anchor 的负 part 数量 | 1 | **仍为1** |
| 模型 LR | .1→.005，300轮 cosine | 相同，没有随 batch 翻倍 |

历史原版目标也是300轮、307步/轮，但实际日志有301行且早期重训一次epoch5，没有逐step身份记录；不把它的实际更新数未经核对写成92100。

V6-B0-64 已有完整监测证明：每轮9792个唯一实例、0重复、0补齐、丢48；累计第2轮已经见过全部9840实例。每轮40类均被使用，global batch 的类别数平均27.7815，范围18–36。单轮多丢32例只让总体覆盖率下降约0.325个百分点，当前证据不支持“V6-B0-64大量漏用训练集”的解释。

### 3.2 intra 的 flip 改成 global64；没有自动增加负样本

共同基础目标为：

\[
L_B=\frac1B\sum_{i=0}^{B-1} CE_i^{\varepsilon=.2}
 +.01R_{contr}^{(B)}+.01R_{hier}^{(B)},
\]

\[
R_{contr}^{(B)}=\frac1B\sum_i
\left[d_1(\mu_i,\nu_i)-d_1(\mu_i,\nu_{B-1-i})+4\right]_+,
\]

\[
R_{hier}^{(B)}=\frac1B\sum_i
\left[-d_1(0,\mu_i)+d_1(0,\nu_i)+1000/N_{part}\right]_+.
\]

原 V6-B0-32 是 `part.flip(0)`，位置0对应位置31；V6-B0-64 按 rank0、rank1顺序 gather 后做 global flip，位置0对应位置63。V6-B0-64 的 flip 负 part 必然来自另一 rank，不能用每卡 local flip 替代。

两者仍然只给每个 whole 一个负 part，并允许自然同类负配对。V6-B0-64 不做所有63个候选的对比损失，也没有因为 batch 加倍把每个 anchor 的负样本数加倍。偶数 batch、无放回且无重复时，flip 不会把一个位置与自己或相同实例配对。

原训练随机样本服从数据集类频率，而非类别均匀分布。同类 flip 的概率由类频率和有限集抽样共同决定，扩大 B 本身不意味着同类碰撞概率必须大幅增加。V6-B0-64 逐step记录实际碰撞；若比较损失差异，应分别检查碰撞率和碰撞样本的 hinge，而不是把所有负对都称为异类。

V6-B0-64 每个 rank 计算同一个 global64 的均值损失，可微 gather 的反向 SUM 与 DDP 的参数梯度平均抵消，无额外 world-size 乘除。这种梯度路径并不意味着 CE/intra 的归一化失配。源损失值及梯度已有 CPU 验收；真实双卡参数和梯度在每轮首末步的600个检测点差值为0。

### 3.3 BN 仍以每卡32计算，global64没有变成64例 SyncBN

原单卡 V6-B0-32 先 part forward、后 whole forward；两次经过共享网络的普通 BN，每步更新两次。V6-B0-64 同样每卡32、part/whole两次更新，不冻结 BN，也没有使用 SyncBatchNorm。

因此 V6-B0-64 的“64”是**CE/intra和优化更新所用的全局样本数**；BN 每次计算统计仍只看本卡32个样本。DDP 会在外层 forward 前广播 rank0 的 buffer，这不等于合并两卡的均值/方差。

还有一个与总更新数关联的变化：V6-B0-32 每轮307步，共享 BN 的计数每轮约增加614；V6-B0-64 每轮153步，每 rank 约增加306。V6-B0-64 每轮BN running statistics的更新次数与梯度更新次数一起减少，不能仅以“每卡还是32”推断与原训练等价。各 rank 在本步后的 running mean / variance 可以不同，保存与推理主要使用 rank0 对应状态；模型参数/梯度同步不要求每步末 BN buffer 完全相同。

这些区别可能影响 eval 嵌入及分类，但需要无更新 probe 或受控实验确认贡献。仅凭 V6-B0-64 的高 whole 半径或某类测试准确率下降，尚不能确定是 BN 引起。

### 3.4 更新预算与随机流也改变了

V6-B0-64 每轮用的实例数与 V6-B0-32 接近，但更新次数约减半。在 epoch 单位上，两者采用相同300轮 cosine；换成 optimizer step 单位，V6-B0-64 的 LR 衰减过程只经历45900次更新，V6-B0-32 经历92100次。因此“相同300轮和相同LR”并不意味着相同优化轨迹。

V6-B0-64 global64目标的两卡梯度在一次更新中汇合，也不等同于原版依次执行两次 V6-B0-32 更新：后一次 V6-B0-32 会在已经更新的参数上 forward/backward。Rcontr还存在跨卡端点耦合，不能把它理解成两个独立V6-B0-32损失的平均。即使对完全相同的样本，两种操作也通常不相等。

此外，V6-B0-64 使用每epoch / step / rank的分开随机流、共享 whole / part 点数、4 workers/rank；原源码一次设seed后连续消费 DataLoader、增强和裁剪随机数，workers8。初始化seed相同只能限定一部分身份，不能保证实例顺序和part中心、点数或增强逐位相同。

共同保留的核心算子包括 part 视图复写 whole、首层固定512 FPS、原 `torch.max` hinge零点梯度、CE eps=.2、两项intra各.01、RiemannianSGD及norm1裁剪。V6-B0-64 没有加入 HIER特有cap、反向hook或代理。

## 4. 历史日志、续训与 checkpoint 字段陷阱

### 4.1 “Valid”其实是 test；epoch 和 resume 不能误读

历史日志列 `Valid-Loss / Valid-acc-B / Valid-acc` 分别是官方 test 的 CE / AA / OA。原源码从0计epoch，新包装 JSON 从已完成轮数1计；历史 `epoch229` 对应名义第230轮。

历史 `out.txt` 确认早期续训。当前源码虽然打印“Resuming last checkpoint”，实际读取的是 `best_checkpoint.pth`，并令 `start_epoch=checkpoint['epoch']`，没有加1。日志中的epoch5因此出现两次；历史日志共301行。这还改变后续随机流和局部LR轨迹，所以历史seed4780不是无中断源码默认seed22的严格对照。

历史运行目录没有完整旧软件环境或源码快照。现有文件与当前原路径的主模型/入口一致性已核对，但不能承诺重新运行能逐位生成历史权重。

## 5. 本次 whole / part 几何对比协议

### 5.1 六份模型用相同输入，完整 train 和 test

使用 [compare_hycore_class_geometry.py](../../inter_hierarchy_MN40/compare_hycore_class_geometry.py)，逐一检查上述六个best/last模型；不加载teacher或HIER proxy，不做backward或optimizer更新。

- 完整训练集9840、完整官方test2468；保持固定的HDF5实例身份及相同数据/ID哈希。
- whole为每个对象原始前1024点，**无增强、无局部whole裁剪、无part复写**。
- 每个实例按split、实例ID、seed22确定一个固定中心；围绕这个相同中心按欧氏kNN距离取200 / 400 / 600点。
- 三种part是嵌套邻域，共享中心；相同点距用原点索引确定排序。六份模型收到完全相同的输入坐标。
- 原FPS首层仍请求512个位置，part不足512时保留源行为。
- 全部模型处于eval，冻结参数；检查推理前后全部buffer（包括BN均值、方差、计数）保持不变，检查源whole数组不被part操作改写。
- FP32执行原网络，随后以FP64计算c1几何，无额外投影或cap；运行前后checkpoint文件SHA256必须相同。
- 默认推理分块16；若添加32分块核验，应作为另一个明确报告的有限数值一致性检查，不把batch分块变化混入模型间比较。

这一协议用于比较**已训练模型的表示**，不是重放训练时whole/part采样或复写状态。因此clean评估的Rhier残差与训练telemetry的Rhier不会天然一致。

### 5.2 半径和深度的单位

曲率固定c1时，欧氏半径和双曲原点深度分别为：

\[
r(x)=\|x\|_2<1,\qquad d_0(x)=2\operatorname{artanh}(r(x)).
\]

二者单调对应，但尺度不同。r接近1时，很小的半径差会变成较大的双曲深度差；不能只看半径保留两位小数后都写“.99”，就认定表示相同。

球边界附近率使用原监测阈值 `r≥.99599`。它表示靠近原FP32数值球边界，**不是实际投影触发次数**，也不是新增截断机制。clean whole不能直接与训练模式whole边界率作模型间因果比较。

旧9月22几何摘要中名为 `radius` 的字段有值大于1，实际按 `d0` 双曲深度解释。比如历史best clean test chair均值4.106951、lamp3.965020、sofa4.239538、table3.110556；这些旧whole摘要没有part，也没有完整本次统一协议身份，不能直接与V6-B0-64欧氏半径或训练位置汇总相减。本次新推理结果取代旧摘要作为主要比较依据。

### 5.3 逐类应报告什么

每个split、模型及part大小独立统计，分母清楚：whole每对象一条；每个part大小也每对象一条，不把200/400/600三个part混成同一总体。

| 指标 | 含义及边界 |
|---|---|
| class count / whole OA / smoothed CE | 该类样本数、对象分类是否正确与置信误差；test小类仅20例，一例改变5个百分点 |
| whole r / d0 的mean、p10、median、p90 | 类别whole距原点的分布，分别保留欧氏与双曲单位 |
| part r / d0 的同类分布 | 固定局部邻域在该模型中的深度；不是有标注语义部件 |
| whole−part双曲深度差 | `gap=d0(whole)−d0(part)`；正值只表示whole更外侧 |
| Rhier残差 / 满足比例 | `[1000/Npart−gap]_+`及零残差比例；仅针对本次固定clean邻域 |
| whole–part双曲距离 | 表示正对在球内实际距离，不等价于径向间隔 |
| whole–part夹角 | 原点观察两嵌入的方向差；若方向未定义，应剔除并报告计数 |
| near-boundary比例 | 用同一阈值检查whole与part；不能当实际projection计数 |
| part预测与对象标签一致率 | 局部邻域沿用whole分类器后的对象类别一致性；**不是语义part识别准确率** |

新clean推理没有通过整批flip来计算Rcontr；如果需要比较对比项，必须在另一个固定batch、明确负配对的probe中报告，不能凭逐类whole/part半径猜测它的值。

### 6.3 更重要的结构发现：原版的clean inference也没有完整保留intra间隔

对固定part400，理论Rhier要求gap≥2.5。三组best test中whole比part更深的比例仍多数，但达到margin是另一回事：

| best clean test / part400 | whole更深比例 | Rhier>0比例 | 未加权Rhier均值 | whole–part平均夹角 |
|---|---:|---:|---:|---:|
| ORIG-B0-32-S4780 | 80.43% | 95.50% | 1.8924 | 11.27° |
| V6-B0-32 | 81.20% | 96.35% | 1.8474 | 12.45° |
| V6-B0-64 | 78.44% | 97.81% | 2.0290 | 9.69° |

六套权重的part200 clean test **全部** Rhier>0（要求gap≥5）；part600也有约96.5–98.1%的违反比例，且部分part比whole更深。更多点的局部邻域平均更深这一趋势仍在，但固定clean表示没有严格实现原训练margin。

这不是“源码没有训练intra”的证据：训练使用随机点数、增强、whole局部裁剪、part复写和训练BN，而上述使用固定clean whole、固定局部patch和eval BN。它确实说明 **训练loss较小不能直接证明推理嵌入具有同样的part–whole层次**，且这个问题在历史原版就存在。

### 6.4 固定batch探针：分开关系重组、BN组别与BN模式

使用同一批256个独立训练实例（4×64）、同ID固定part400、whole前缀复写；不做增强或首次whole重排。所有条件都不反传、不更新参数。训练BN条件中两组32各从相同checkpoint buffers开始，改变分组后按ID回排并保持相同negative ID映射。均值是四个固定batch的观察，不是全训练分布或置信区间。

**A．固定eval输出，只改负配对：** CE及Rhier严格相同，Rcontr变化如下。

| best权重 | global64 flip Rcontr | 两段local32 flip Rcontr | global−local |
|---|---:|---:|---:|
| ORIG-B0-32-S4780 | 0.3122 | 0.4472 | -0.1350 |
| V6-B0-32 | 0.3767 | 0.4899 | -0.1131 |
| V6-B0-64 | 0.2811 | 0.3654 | -0.0844 |

这确认配对变更能改变intra梯度所针对的约束。本次global/local同类负比例为3.90625%/6.25%，来自同一有限256例的不同配对；**不能据此宣布global64总体同类碰撞率更低**，随机无放回时的期望由类别频率决定。

**B．固定权重与相同已复写输入，只切换eval / train BN：**

| best权重 | eval平均depth gap | train-BN平均depth gap | eval Rhier | train-BN Rhier |
|---|---:|---:|---:|---:|
| ORIG-B0-32-S4780 | 0.7674 | 3.0051 | 1.7544 | 0.0704 |
| V6-B0-32 | 0.8312 | 3.1167 | 1.6966 | 0.0276 |
| V6-B0-64 | 0.5750 | 3.0601 | 1.9367 | 0.0201 |

同样输入下，原版gap从.767变3.005，V6-B0-64从.575变3.060；Rhier残差明显缩小。这里已经控制whole复写/part中心，差异来自模型的训练BN与eval BN状态，而不是重新采样或优化。**三组都有强BN模式依赖；并非V6-B0-64新增的独有现象。**

**C．两者都用train BN，只改local32成员，负配对ID保持不变：**

| best权重 | whole逐例平均绝对Δd0 | part平均绝对Δd0 | whole平均双曲位移 | part平均双曲位移 | 分类预测改变 |
|---|---:|---:|---:|---:|---:|
| ORIG-B0-32-S4780 | 0.0916 | 0.3418 | 5.7268 | 1.4066 | 0.3906% |
| V6-B0-32 | 0.0896 | 0.2564 | 5.9499 | 1.2746 | 0.0000% |
| V6-B0-64 | 0.0650 | 0.2603 | 5.7231 | 1.1578 | 0.0000% |

改变BN组使相同whole在双曲空间产生约5.7–6.0的平均位移，但半径/深度变化较小、分类几乎不变。接近边界时角向变化会被双曲距离放大，不能把位移5.7解释为半径增加5.7。这是当前权重下分组影响几何的直接证据，**不是batch划分导致分类失败的证据**。V6-B0-64的敏感度没有明显超过原版；表中不执行BN64，所以不能称作SyncBN64与localBN32对照。

**D．仅用一次part→whole前向得到的各组BN buffers做clean64推理：** 原版预测变化平均.390625%、最高1.5625%；V6-B0-32和V6-B0-64均0%。whole深度平均变化为.04535/.00758/.02193。均值来自4个batch×2种分组×2个rank的16套buffer条件，全部在同一64个clean实例上评估；不是1024个独立实例。这次小probe没有发现rank0/rank1选择造成大幅分类变化；它不排除完整训练累计BN状态影响，也不替代全test buffer对照。全部原buffers/RNG在结束后恢复。

## 7. 对“我们的batch划分有没有影响”的判断与下一步

1. **有协议影响，尚未发现实现错误。** global64改变负part映射、损失平均的实例数量、梯度/动量更新次数和BN统计轨迹；它不等价两次V6-B0-32更新。当前未发现多乘/少除2、重复采样、大量漏类或双卡参数不同步。
2. **分类没有被明显破坏。** V6-B0-64 best略高、final接近；原版本来也有后期拟合与flower_pot困难。单seed/历史resume/不同随机流限制因果判断。
3. **几何不是完全不受分组影响。** 同一权重、同一输入、同一negative ID，local32成员变更即可移动whole/part；但几何变化与分类变化不等价。V6-B0-64 best径向更浅、last相对更深，不能统一归因为向外漂移。
4. **更优先的问题是结构在train/eval之间能否保持。** 原版和V6-B0-64都在train BN形成较大part–whole gap、eval时大幅缩小。对CE可能仍可分类，对依赖样本距离的HIER mining/祖先布局则需要单独检查。不能用训练intra低loss或clean分类高OA代替关系稳定性证据。
5. **建议先做无更新的关系稳定性诊断。** 固定同ID，比较train/eval与不同local32组的互惠邻居、祖先身份及深度次序；同时区分保存running buffers与当前batch统计。若确认BN是inter的主要不稳定来源，再评审保持HyCoRe基础算子兼容的BN策略。当前数据不支持直接把BN冻结、改为SyncBN，或仅调loss系数。
6. 要评估batch64净收益，需明确按epoch还是optimizer-step对齐预算，并固定数据/选模/seed等；一次后验probe不是完整训练消融，本次没有自动追加主训练。
