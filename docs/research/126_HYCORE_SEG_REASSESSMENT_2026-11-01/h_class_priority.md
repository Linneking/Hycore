## 1. 接受的范围调整

- 用户指出分类HyCoRe本身也可能没有良好的margin可达表现。不能把margin满足率当成正则有效性的必要条件，更不能因为hinge长期不为零就认定方法失败。可达率（当前whole固定时part是否存在可行半径）、满足率（实际whole/part是否满足）与任务收益是三个不同量，最多用于机制分析。
- 用户认可I是分类启发的变体，而不是分割论文原流程。保留这一方法标识。
- 不再把I的BN诊断列为下一步或后续H实验的前置条件。I的低表现不能确定各改动的因果贡献，但不妨碍将研究资源集中到更好的H。H的正则支路绕过M、每batch一次whole前传；主支本身仍含两层M。
- 后续固定H主支，主要看Class mIoU和各物类内部的部件识别；Instance mIoU仍作为共同报告指标。当前不自动切换checkpoint选择指标或更改历史best定义。

数据来自 [server_evidence.json](server_evidence.json)。下表使用两组各自best Instance检查点（H e197，H0 e173），因此是描述性分解，不是同轮或多seed因果证明。

Class mIoU是16个物类IoU的平均，所以每类差值除以16。rocket与motorbike合计贡献约−1.279pp，整体Class差值是−1.272pp；其余14类合计净贡献约+0.007pp。也就是说，这个H/H0宏平均差距几乎全部来自两类。

同一份证据的最终e200也显示两类退化，不能只用best所在轮次不同解释现象。但这仍受单seed及不同硬件历程影响。低Class问题还包含H0相对欧氏基线的共同差距，不能只恢复这两类就宣称完成复现。

## 3. 下一步要回答的问题

1. **H与原DGCNN、H0分别差在哪里？** 使用同样定义的各物类IoU、每个部件recall、部件混淆、逐对象预测直方图，先聚焦rocket、motorbike及H/H0都弱的类别。报告best与共同轮次/末段表现，避免单独挑一个最差batch。
2. **是没有学会某些部件，还是边界质量差？** 区分只预测一个部件、少数部件recall为零与各部件都预测但边界错误。重复相同IoU是线索，不是已证明常量预测。
3. **问题是否由R放大？** 对表现退化类别分别观察CE、Rcontr、Rhier在共享层上的加权梯度方向；H/H0共同存在的问题优先考察分类读出和点级监督，主要在H出现的退化优先考察两正则各自影响。

这三项面向任务错误来源；margin/贴边率只作为附带解释，不设“必须先提高几何满足率”的门槛。

## 4. 后续修改按证据选择

- 若H/H0都有相似部件识别问题，保持H主支后优先选择一个分类读出或点级监督改动。训练logit scale/真正双曲MLR仍是候选，不先认定它们一定提升Class mIoU。采用同改动下R开/关配对，避免把读出收益计到正则名下。
- 若主要是H的特定物类被正则拖累，优先拆开contrast-only与hier-only，在H上定位损害来源；不为此重新扩展I。
- 若确认少数物类或少数部件的训练监督不足，再设计类别/部件权重。物类频率和物类内点标签频率是不同层次，不能只因为Class较低就立即改变batch组织。
- 采用Class mIoU作为重点后，不能只报告“最佳Class”来改善表面数字；新模型选择规则必须预先定义，并与可比较对照一致。最终结论还需多个seed与独立测试。
