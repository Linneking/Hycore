## 1. 我们要解决什么问题

我们正在把 HIER 的实例间软层次引入 HyCoRe 的点云分类训练。

HyCoRe 已有的是 **同一实例的 whole–part 关系（intra）**：完整物体嵌入位于较深处，子点云嵌入位于较浅处，同时让正 part 比其它实例的 part 更接近自己的 whole。HIER 引入的是 **不同 whole 实例之间的关系（inter）**：学习一组不绑定类别的代理，让相近实例有较细的共同祖先，较大的实例群有较粗的共同祖先。

我们的工作假设是：HIER 可以调整 whole 嵌入，使它包含类内形态关系和跨类亲缘；part 通过原 HyCoRe 的共享网络与 intra 约束随之适应。分类 CE、intra 和 inter 作用于同一 whole 表示。

**代理可以是抽象共同祖先，不要求对应真实部件，也不要求给 part 增加代理约束。** 例如两个相近实例对应代理 \(p_{ij}\)，加入第三个较远实例后对应 \(p_{ijk}\)，我们希望前者体现后者之下的细分关系。是否形成这种关系，需要实验检验；论文主张可以随结果调整。

当前 V5 的训练目标为：

\[
L=L_{\mathrm{CE}}+0.01R_{\mathrm{contr}}+0.01R_{\mathrm{hier}}
  +\lambda_H\bigl(R_{\mathrm{sample}}+R_{\mathrm{proxy}}\bigr),
\]

其中前 20 轮 \(\lambda_H=0\)，第 21 轮起 \(\lambda_H=0.5\)。CE 使用 HyCoRe 的标签平滑；两个 intra 项保持原形式；两个 HIER 项共用发布源码的祖先选择及三个 hinge，合称一个 inter。

## 3. 当前实验进展

### 3.1 V4：出现改善信号，但基线本身退化

V4 三组均完成 200 轮，使用同一 seed=22、8856 训练 / 984 验证实例；训练结束后，用验证选出的 checkpoint 评估正式 test。

本节 V4 旧称 B0/H3/H5 已分别映射为下表的 LEGACY-V4 展示名；三组均使用 4×8 队列、child 独立存储及仅 whole 更新 BN 的协议，不属于当前 HyCoRe shuffle 基线家族。

| V4 组别 | 最佳验证 OA | 对应 test OA | 末轮验证 OA |
|---|---:|---:|---:|
| LEGACY-V4-B32-Q4x8-BN1：CE + intra | 89.84% | 88.37% | 78.35% |
| LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1：LEGACY-V4-B32-Q4x8-BN1 + HIER，sample K=3 | 90.35% | 89.55% | 80.59% |
| LEGACY-V4-HIER32-K5-W20-R20-Q4x8-BN1：LEGACY-V4-B32-Q4x8-BN1 + HIER，sample K=5 | 89.63% | 88.17% | 71.85% |

LEGACY-V4-HIER32-K3-W20-R20-Q4x8-BN1 比 LEGACY-V4-B32-Q4x8-BN1 的 test OA 高约 1.18 个百分点，是值得保留的单 seed 信号。但 V4 同时改变了 HyCoRe 的输入和训练协议：

- 取消了 part 采样对 whole 输入的切片覆写。
- part 前向使用 batch 统计，却不更新 BN 运行统计。
- 改成 4 类 × 8 例的 batch，且整轮类别出场存在时序偏置。

这些改动使 LEGACY-V4-B32-Q4x8-BN1 不能代表原版 HyCoRe。LEGACY-V4-B32-Q4x8-BN1 的 clean train eval OA 也从最佳模型的 91.73% 降到末轮的 81.37%，所以后期问题不能全部解释为通常的未见数据过拟合。输入分布、BN 和训练协议的影响需要拆开。详见 [V4 经验教训](12_V4_LESSONS_2026-10-03.md)。

历史原 HyCoRe checkpoint 的 test OA 为 94.044%，但其划分、预算和训练协议不同，不能直接与 V5 验证 OA 比较。

## 4. 现在最需要解决的困难

### 4.1 有足够关系可训练，不等于学到了好的关系

训练前的固定参考特征检查中，K20 的合格 anchor 比例约 60.39%，但跨增强的跨类互惠边 Jaccard 仅 14.32%；whole 半径与互惠 degree 的相关性较强。这些是旧参考权重上的诊断，不是当前 V5 的结构结论。详见 [K 扩展诊断](16_V5_TOPK_FOLLOWUP_2026-10-03.md)。

在随后读取的 V5 第 143 轮监测中，sample 合格 anchor 已达到 **99.98%**；pair / triple 选中同一代理的碰撞率约 **0.39%**；至少一个未被 mask 的 hinge 大于零的三元组占全部 draw 约 **6.81%**。这些比例回答的是不同问题。

低 active 比例可能意味着约束已满足，也可能意味着候选关系容易、选择发生退化或层次信息不足；需要同时检查关系稳定性和祖先结构。不能把低 inter loss 或高 anchor 比例直接当作成功证据。

实例利用率也要单独看：V5-HIER64-K20-W20 第 143 轮的唯一训练实例覆盖率约 **66.40%**，V5-B0-32-CAP200 第 161 轮为 **72.27%**。V5-HIER64-K20-W20 的 draw 更多，但类别均匀和类内有放回使大类重复、漏采仍然存在；200 步没有自动实现原 HyCoRe 的整轮遍历。

### 4.2 whole 很接近球边界，需要检查半径是否主导结构

同一轮 V5-HIER64-K20-W20 中，whole 的 \(\|z\|\ge0.99599\) 比例约 **94.34%**；V5-B0-32-CAP200 第 161 轮为 **68.66%**。V5-HIER64-K20-W20 模型梯度裁剪在约 16.5% 的步触发，V5-B0-32-CAP200 为 17.5%。

边界比例是映射后输出位置的统计，不是额外截断的触发次数，也不能单独证明 HIER 导致数值问题。两组协议不同。这提示我们要按半径分层检查代理邻域、稳定性和关系质量，不能只看一张二维球图。

### 4.3 相似的最近四例，可能来自多个原因

可能包括主任务已经形成的类别聚类、特征本身的姿态/形态相似性，以及层次代理额外形成的组织作用。需要用同一批特征和明确对照，把代理学习的贡献识别出来。

发布源码的 sample 候选图使用 \(\exp(-d_c(z_i,z_j))+\mathbf1[y_i=y_j]\)，proxy 候选图不加标签。这个同类加分参与训练关系选择，也可能促进同类聚集；最近四例图本身应按原始距离检索。

同类纯度高可作为局部聚集证据；进一步的类内形态细分和多级共同祖先，应分别检查。我们不预设它们必然失败，也不预先把同一个组合层次的设想排除。

### 4.4 官方 HIER 和点云融合仍有协议差异

官方图像入口通常使用预训练主干、冻结 BN 运行统计、PA 等度量学习目标，以及 \(c=0.1\) 和额外截断/反向处理；我们使用从头训练的 HyCoRe、CE、\(c=1\)，并暂时关闭上述额外机制。V5 还原了关键 loss 和关系选择，但没有声称完整复制了官方训练协议。

因此同学的官方复现很适合提供机制参照：哪些代理现象在原流程中存在，哪些在融合后消失或改变。

## 5. 建议给同学安排的任务

**主任务：做一个能同时分析官方 HIER 与 V5 的只读代理结构评估器。先完成任务一、二，再检查任务三。** 使用已有 checkpoint 和特征缓存即可；首阶段不需要再开完整训练。

### 任务一：把最近四例的观察变成全量定量结果——最高优先级

**问题：训练代理的邻域是否比随机代理更有组织性？漂亮案例占整体的多少？**

操作：

1. 固定官方代码版本、数据划分、checkpoint、实际曲率、代理类型和映射方式。
2. 对全部层次代理，用原始高维双曲距离检索最近 4 / 8 / 16 个样本；保留 ID、标签、距离、代理半径。展示不加同类 boost、不预筛类别。
3. 输出全量图册，并按代理半径分层统计。单独展示靠近边界的代理，复核 Fig.5 式现象；同时保留中心代理和失败案例。
4. 分开统计两种关系：每个代理检索最近样本；每个样本分配到最近代理。报告后一种关系的占用分布、占用熵及对应的有效数量、零分配比例，以及前一种关系的类别组成和邻域重叠。若占用比例为 \(f_p\)，有效数量可定义为 \(\exp(-\sum_p f_p\log f_p)\)，它描述分配是否集中，不直接定义哪些祖先有效。
5. 固定同一批已训练样本特征，保留每个代理半径、随机化方向，重复至少 5 个随机种子作为对照。它检查代理方向与样本结构的对应是否超过同半径随机参照；特征和代理是联合训练的，不能由此隔离代理方向学习的因果贡献，也不能由此判断全部 HIER 收益。
6. 若已有同协议 ML-only checkpoint，另做对照；若没有，明确记录缺失，先完成缓存层面的分析。

**注意：** 每个代理都能检索四例，所以图册“每行都有四张图”不代表每个代理都有效。反过来，粗层祖先可能不成为任何样本的最近代理；零分配也不自动意味着代理死亡，要结合 pair / triple 和 proxy–proxy 使用率判断。

**交付：** `manifest.json`、`proxy_stats.csv`、完整邻域图册、学习代理与随机方向代理的分布比较、失败案例。

**验收：** 覆盖全部代理；结果可重算；检索使用正确的球内代理和曲率；同时报告平均值与分布；结论能说明对照检验的范围。没有改善也算完成任务。

### 任务二：检查稳定性和真正的类内细分——第二优先级

**问题：代理周围的相似性是否超出“都是同类”，是否经得起输入变化？**

操作：

1. 对相同样本 ID 导出干净输入和两个增强视图。记录每个样本最近代理保持率、最近 4 个代理的集合 Jaccard，以及每个代理最近 4 个样本的集合 Jaccard。
2. 从全量结果中按固定规则抽取样本，不能只选最漂亮的代理。按类别、代理半径及占用量分层报告稳定性。
3. 选少量类别做独立属性评估：图像可以使用视角/姿态等标签或盲评；点云可以使用类内整体形态盲评、规范化后的几何距离等辅助信号。独立信号不要求识别共享真实部件。
4. 在同一类别内比较“同代理”和“不同代理”的实例对，并加入类内随机配对、普通特征最近邻对照，避免把类别一致性直接当成形态层次。
5. 对人工评估记录抽样规则与样本数；对几何描述符记录归一化和对齐方式，它们是辅助证据，不自动等于语义真值。

**交付：** 稳定性指标、类内属性/形态比较、抽样及盲评说明、稳定和不稳定的代表案例。

**验收：** 同一 ID 跨视图能对应；对照不受类别比例差异驱动；报告不确定性和失败类别。跨 checkpoint 比较时匹配邻域/代理，不能默认相同编号始终具有同一语义。

### 任务三：检查抽象共同祖先的两级关系——直接对应我们的设想

**问题：局部聚集之外，\(p_{ij}\) 和 \(p_{ijk}\) 是否体现可重复的细分/粗分关系？代理之间有没有对应关系？**

官方选择的 cost 为：

\[
C_{ij}(p)=\max\{d_c(z_i,p),d_c(z_j,p)\},\qquad
C_{ijk}(p)=\max\{C_{ij}(p),d_c(z_k,p)\}.
\]

训练分别对 \(-C_{ij}/\tau\) 和 \(-C_{ijk}/\tau\) 做独立的 hard Gumbel 选择。对选出的两个代理使用：

\[
\begin{aligned}
\ell_{ijk}={}&[d_c(z_i,p_{ij})-d_c(z_i,p_{ijk})+m]_+\\
&+[d_c(z_j,p_{ij})-d_c(z_j,p_{ijk})+m]_+\\
&+[d_c(z_k,p_{ijk})-d_c(z_k,p_{ij})+m]_+.
\end{aligned}
\]

若两个选择是同一代理，该 draw 被置零；源码仍对全部 draw 求均值。proxy–proxy 项用同一形式，把三元组元素换成代理。

操作：

1. 先在固定实例 ID 的评估 batch 上按源码互惠规则抽取，保存 batch ID、K、T 和 seed，再按 \(i/j/k\) 的类别组合分层。用于结构判断的集合使用不同实例 ID；源码允许的 self-k 和重复 ID 另外报告，不改变训练。若另用独立形态信号定义三元组，单列生成规则和结果；纯类内的三个不同实例不属于当前每类两例 batch 可直接生成的关系。
2. 同时输出确定性 `argmin cost` 诊断和多个随机种子的 Gumbel 结果。确定性结果便于复核，但不能称为训练中的实际随机选择。两者选择分布不同，碰撞率分别报告；不能仅凭 argmin 频繁碰撞认定训练退化。
3. 报告 pair / triple 代理碰撞率、非碰撞 draw 的三个 hinge 满足率、选择稳定性、代理使用量。
4. 检查深度差
   \(h_c(p_{ij})-h_c(p_{ijk})\)，其中
   \(h_c(p)=2\operatorname{atanh}(\sqrt c\|p\|)/\sqrt c\)。
   正值对应 pair 代理较深；**它是待检验结果，三个 hinge 没有直接保证径向顺序。**
5. 对 proxy–proxy 三元组做同样统计。若要画父子图，使用原始高维空间，声明建图规则，报告环、连通分量和跨视图稳定性。

官方 UMAP notebook 的灰线是在降维之后按距离和半径规则另行构造的，不能当作训练直接输出的离散树。二维图用于展示，定量关系从高维计算。[官方可视化 notebook](https://github.com/sung-yeon-kim/HIER-CVPR23/blob/3986a744a1a54fd357e307d1cb3f2e81910b9ffc/examples/umap_vis_cars.ipynb)

**交付：** 固定三元组集、祖先统计、proxy–proxy 统计、成功/失败案例及关系图。允许代理是抽象祖先；不要求给它命名为某个实体 part。

**验收：** 碰撞、约束满足和无效 draw 的分母分开；不从几个最近四例图宣布已得到完整树；也不因代理无法对应真实部件而否定结果。

## 6. 统一接口，让同学的结果能直接用于 V5

建议评估器读取如下缓存。这里是交付规范，仓库还没有实现该评估器。

| 字段 | 要求 |
|---|---|
| `sample_id`, `label`, `view_id` | 稳定实例身份、类别、增强视图；重复 ID 明确记录 |
| `embeddings` | `[N,D]` 的球内 whole / image 嵌入 |
| `hierarchy_proxies` | `[P,D]` 的球内层次代理；不要直接把切空间参数当球坐标 |
| `c`, `D`, `P` | 使用实际值；官方 checkpoint 与 V5 可以不同 |
| `train_topk`, `display_n` | 训练关系 K 与展示数量分别命名 |
| `checkpoint_hash`, `code_commit`, `split` | 结果身份与数据划分 |
| 映射、截断、标签 boost 配置 | 解释当前特征和关系从哪里来 |

导出时使用 eval 模式、不更新 BN，固定输入与增强种子。导出一次后，检索和三元组审计可分块在 CPU 完成，不要求占用当前主训练 GPU。

同学先在官方 HIER 的已有缓存上完成接口；V5 完成后，我们提供验证选中模型的 whole / proxy 缓存，再运行同一套评估。训练集与验证集结果分开报告；图像检索数据中的未见类别迁移也另外注明。原始高维缓存是定量依据，UMAP 坐标仅用于展示。不同曲率下不直接比较未经解释的绝对距离数值。

推荐首批交付只包含：

- 一个可运行的评估入口和配置示例。
- 一套官方 HIER checkpoint 的全量报告及随机方向对照。
- 一份短结论：哪些代理现象稳定，哪些只在精选展示中出现，是否值得继续检查两级祖先关系。

代码和小型摘要可以进入版本管理；数据、checkpoint 和完整特征缓存留在约定的非仓库位置。

## 7. 如何根据结果推进主项目

| 同学得到的结果 | 对下一步的帮助 |
|---|---|
| 学习代理在预先声明的指标与重复随机参照下稳定占优，且有稳定类内属性细分 | 优先把同一评估接入 V5，判断融合是否保留该机制 |
| 最近四例好看，但全量指标或增强稳定性没有优势 | 先检查检索、半径偏置及特征来源，减少继续盲调 K / 代理数量 |
| 局部邻域稳定，但 pair→triple 深浅/约束关系不稳定 | 重点检查祖先选择、碰撞和 proxy–proxy 项，而不是增加 part–proxy 任务 |
| 原 HIER 稳定、V5 不稳定且贴边明显 | 为曲率、额外截断/反向机制或优化协议的后续单项对照提供依据 |
| V5 分类提高，但代理结构证据不足 | 分别报告分类收益和结构证据，继续补严格同协议 HIER 关闭对照 |

当前训练先完成，不据此文档启动新实验矩阵。下一轮需要把基础操作、采样协议和 HIER 目标的影响分别对照。
