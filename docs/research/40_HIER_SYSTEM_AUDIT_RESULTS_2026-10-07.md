# V5 / V6 / V7 全系统审查结果 — 2026-10-07

本次按用户已批准的[38号计划](38_HIER_POSTRUN_AUDIT_PLAN_2026-10-07.md)实现并实际串联审查。结论是：**V6排除了退化self-k关系；V7解决了代理数值饱和，扩大了样本祖先参与范围，但热点覆盖与类内形态结构的收益仍不一致。** 分类结果有所回升，尚不足以证明inter目标形成了有效的软层次。

## 实现与证据范围

独立工具目录为`tools/hier_postrun_audit/`，不改生产训练。它输出离线HTML、科学图PNG/SVG、JSON/CSV与缺失能力表，包含逐轮几何、代理ID生命周期、全候选检索、固定噪声机制对照、独立形状检验、共享编码器梯度及跨版本收益账本。输入身份不一致时拒绝轨迹配对；没有保存的数据明确缺失。

本次读取V5的6个、V6的7个、V7的11个及匹配B64的7个真实检查点，共31个。每个检查点冻结导出相同8856个训练对象，clean first1024/eval BN、seed22、batch32；实际输入字节SHA一致。独立形状审查覆盖15个检查点、相同320个对象（每类8个）、完整8856候选，使用FPS64点、原尺度与中心单位RMS两套形态距离。机制审查完成11个检查点、固定balanced64及8组Gumbel噪声。只读取已保存validation选模型和最终test结果，没有新增validation/test前向或优化器更新。

V5总训练200轮，V6/V7为300轮；V6→V7同时改变warmup、权重、初始化和post-Adam参数约束。本次是单seed历史比较，不能为某一个参数分配独立因果贡献。B64是同global64协议的无HIER对照；其独立结果不虚构共同前缀中缺失的e20。

| V6→V7 | e300代理数值饱和323/512→0/512；样本祖先188→267；有效代理155.46→197.59 | 原始距离top4覆盖28→27；后期关系仍集中；选择稳定性没有全面提升 |
| V7→匹配B64 | 部分检查点的双曲距离与独立形态相关性更高 | 最终近邻形态改善没有持续超过基线；类间、类内收益并不一致 |

### 1. V6修正了错误，不能据此断言结构改善

V5及所参考的原始实现允许self-k形成退化关系，V6排除了这类候选；它不是我们移植时漏排而单独引入的错误，排除也改变了抽样分布和目标。此前审查发现V5约2.10%的self-k抽样贡献了末40轮约37.20%的sample损失，因此排除有明确理由。不过两版的raw损失和hinge比例不能直接作为结构优劣指标；须先排除V5自碰撞，再在共同训练窗口比较。V5缺完整代理ID使用记录，不能追溯其全程休眠/再激活。

### 2. V7数值约束有效，浅、深两群仍然存在

共同e300，V6的323个数值饱和代理全部在324个sample-inactive代理中；188个实际样本祖先没有饱和。used/inactive的双曲深度中位数分别为1.748和7.6004。V7这两群为267/245个，中位深度2.272/5.939，全部没有数值饱和。

V7将实际保存切空间参数限制在模长3内，对应c=1的原点双曲深度上限6，阻止它越过数值投影阈值。它没有把所有代理统一放缩到同一半径。V7初始化实际深度约2.240，是初始化whole中位深度2.489的0.9倍；不是固定深度5。

上述样本使用数和有效代理数统一取`sample / noncollision / combined(pair+triple)`，优化期与warmup监测分开。V6 e99–300的样本祖先池并集严格188、交集186，仅两个ID各短暂停用，无新代理进入。V7历史重新激活涉及79个代理、376次事件，V6为21个、23次事件。V7参与范围更丰富，但也有长时间休眠代理。sample-inactive不等于完全死亡：e300代理分量仍硬选择V6全部512个、V7的510个祖先代理。这里的hard祖先覆盖不等于endpoint覆盖或非零梯度覆盖，软选择也可给未被硬选中的代理梯度。

### 3. 最近四例仍是热点，且热点早于饱和

| 全8856候选，e300 | V6 | V7 |
|---|---:|---:|
| 512代理raw top4覆盖对象数 | 28 | 27 |
| direction top4覆盖对象数 | 191 | 221 |
| 重复最多的同一四元组 | 397/512 | 287/512 |
| 最热门4对象占全部top4槽位 | 87.40% | 80.47% |

V7降低了重复程度，但没有恢复raw检索覆盖；方向检索在中期更丰富，后期也退化。四例检索最多只有512×4=2048个槽位，因此不能要求它覆盖全部8856对象。

更关键的是：V6 e20仍处于warmup监测阶段、代理饱和为0，却已有477/512代理重复同一四元组，全体仅覆盖7个对象。由此不能把热点全部归因于训练后投影饱和。径向最近邻偏置、代理排布与whole几何的共同作用仍需研究。最近四例是检索观测，不能当作训练中实际选出的祖先/后代关系。

V7 e300的64个形态审查代理raw形态gain为0.5033，但只涉及21对象、4类、11种四元组；51/64代理重复捕获同类的两组四例。按四元组去重后的描述性均值为0.2964。**热点本身更几何一致，并不意味着发现了广泛的类内结构。**

### 4. 训练whole与冻结clean whole须分开

e300实际训练日志中，V6/V7/B64的whole近边界比例约84.75%/74.30%/68.34%；V7训练深度中位数约6.213。但相同对象的clean/eval快照深度中位数分别为4.617/4.808/4.385，近边界比例仅约0.136%/0%/0%。

这两组值来自不同条件。原始crop覆盖、增广和BN模式均可能参与差异，当前审查没有将它们逐一隔离。不能用训练日志饱和率描述全部clean推理嵌入，也不能由一次clean图推断训练中的梯度。

### 5. 可复现性通过，祖先身份稳定性仍弱

同冻结缓存、同query、同Gumbel种子重放一致；这不宣称全部GPU编码器逐位重放。e300改变Gumbel噪声后，sample pair祖先ID一致率V6/V7约0.109/0.149，三元祖先约0.043/0.085。较高的hinge-mask一致率不代表祖先身份一致。

各运行内部同query、同噪声跨e200→300的pair身份一致率为0.445/0.406。各版本的query计划来自自身首个机制快照的挖掘，彼此不保证相同三元组；这只能描述各运行的稳定程度，不能作为跨版本配对检验。缓存whole偏导、真实共享编码器梯度及保存的Adam状态分别报告，不把局部径向偏导直接说成参数的实际更新方向。

## 独立形状验证：有局部收益，尚无全面优势

下表为原尺度shape、同320对象及全候选池的描述性均值，顺序为e100 / e200 / e300。

| 指标 | V7 | 匹配B64 |
|---|---|---|
| 类内双曲距离–Chamfer Spearman | 0.2338 / 0.1671 / 0.1833 | 0.1847 / 0.1546 / 0.1464 |
| 双曲top4形态gain | 0.3177 / 0.2607 / 0.2417 | 0.2528 / 0.2407 / 0.2620 |
| 方向top4形态gain | 0.3363 / 0.2773 / 0.2550 | 0.3627 / 0.2892 / 0.2612 |

gain定义为`1 − 近邻平均Chamfer / 随机同类平均Chamfer`。V7的相关性点估计更高，但最终双曲gain低于B64，方向gain三轮均略低。中心单位RMS处理也呈混合收益。e300只有24/40类的Spearman提升、18/40类的gain提升。这里没有跨seed验证或配对差值置信区间，不能用已有各run区间的重叠宣布显著或不显著。

Chamfer保留旋转并只用FPS64点，是独立几何代理信号，不是形态语义真值或完整层次证明。类别纯度只作辅助；不能以高同类率代替上述检验。

## 下一步方向

下一轮应先验证“实际训练祖先是否对应可泛化的形态关系”，而非仅继续调半径让检索图更好看。优先用冻结权重、小规模同ID对照隔离训练crop/BN条件，以及raw距离与方向关系对挖掘的影响；如改变训练目标，需要与同协议无HIER对照及多seed共同检验。先保留已验证有效的参数约束，不再把数值饱和和热点集中混作一个问题。
