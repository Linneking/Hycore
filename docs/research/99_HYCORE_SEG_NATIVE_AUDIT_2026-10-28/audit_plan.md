# HyCoRe 分类模型到 HyCoRe-seg：源码审查计划

日期：2026-10-28。用户本轮要求：以官方 HyCoRe 的 DGCNN 分类模型为起点，尽量复用已有组件，按分割论文改造；交付审查报告和复现计划。本轮只审查和规划，不实施新模型或启动新实验。

用户三批注后的当前取舍：无类别one-hot、无新增融合桥；省分类末尾global池化并将原linear1改1024→512逐点调用；原内部cat保留，额外绕接仅后续消融；负例保留原flip且统计同类比例，两篇论文负part定义一致的事实与源码实现差异分开记录。早期桥候选由当前报告覆盖，源码审查证据仍保留。

## 1. 审查问题与通过标准

1. 固定官方分类源码身份，区分原实现、本地历史改动和当前分割 v1。
2. 从 `DGCNN.forward` 顺序追踪图构建、逐点编码、全局池化、欧氏映射、双曲嵌入和分类输出；给每一段标明输入输出形状。
3. 检查 `MobiusLayer` 的实际前向及有效权重，不只比较函数名称；包括 `_bias`、`transp0`、初始化、曲率、投影和梯度。
4. 逐式对照分类损失与分割论文，确定能复用的几何原语、必须改变的层次方向、负样本、part 生成位置及池化顺序。
5. 审查分类训练脚本、CE、RSGD、梯度裁剪、数据加载、评估和保存，区分可复用代码与不可照搬的任务协议。
6. 审查当前 v1：保留有用的数据/指标/调度/追踪工具，明确不符合本次源码继承要求的模型路径。
7. 给出一个具体的原生迁移方案、逐组件来源表、必要验收及最小实验顺序；所有未被论文确定的选择显式标为重建约定。

审查通过不意味着达到论文分数。文档需能回答“这个组件来自哪里、为什么调整、怎样核验”，实现阶段才执行数值等价和训练验收。

## 2. 证据优先顺序

- 官方 `diegovalsesia/HyCoRe` 的 DGCNN 分类活动代码；注释中的替代头单独标记。
- HyCoRe-seg 作者接受稿 §3、§3.1、§3.2、§4 及 Fig.1。
- `D:\Hycore` 本地权威代码与当前分割 v1；记录与官方的差异。
- 原 DGCNN / AnTao 仅作为分割任务实现参考和外部基线，不再作为新 HyCoRe-seg 主模型的继承入口。

证据标签统一为：源码事实、论文事实、用户已定、重建约定、待实现验证。

## 4. 本轮边界与沿用决定

不修改原分类实现、现有v1、数据或服务器结果，不终止/重启现有训练。初始审查无服务器动作；用户追问初始化后补做一次服务器CPU原层探针，读取原源码，仅初始化和反传，不使用GPU、不更新参数或服务器文件，不视为v2完整实现或训练。

沿用用户决定：seed4780；层次间隔 `1000/N′`，对比间隔4；分割 train+val 训练、逐轮 test Instance mIoU 选 best、固定200轮，不 early-stop。论文未确定的训练细节不能写成作者原配方。ModelNet40 的其他协议不因本轮改变。

下一版使用独立的 `hycore_seg_v2` 路径。现有 v1 作为旧路线对照保留，不能改标签冒充完成本轮原生迁移。后续实现/新训练另行按用户审阅后的计划推进。
