# H 分割失效定位审查

2026-11-02。用户授权执行诊断计划，并授权有余量时继续审查。四阶段已完成；未启动新的200轮训练。目标仍为超过DGCNN的Class mIoU：历史best-Instance检查点DGCNN 81.777%、H0 76.093%、H复跑74.754%，这些是全测试集历史成绩，下文探针数值不是新模型全测试成绩。

## 主要发现

最有力的证据指向读出及其优化：H的U256、第一M之后的128维特征都仍可被简单线性分类器用于识别多个原头完全漏检的部件。BN切换不能恢复这些零召回，主头CE梯度也能传到U256。尚未证明初始化、logit尺度、权重模长或某个优化超参是唯一原因。

### 1. 训练轨迹

使用H0、H复跑的e0/1/5/10/20/30/40/50/100/150/200共11个实际存档，另含三模型best，共25个配置。每配置三批固定训练物体，每批32，每物体第一2048点。每批七个重点类别各4物体，加4个其他类别物体；批次可能共享物体，不作为96个独立对象。人为增强了小类比例，不代表自然训练batch。

bag ID4、rocket ID43、motorbike ID31/33/34在两模型所有已检查存档上均无召回。H复跑的rocket ID42同样始终无召回；H0在e30仍为0，e40已为70.4%，e200为89.8%。只能说明抽查时刻和固定对象上的轨迹，不能排除存档间曾有短暂召回。

BN统计对一些部件有影响，但这三批中并未使零召回恢复，因此优先级降低，不能泛化为所有BN因素均已排除。

在detached U上重放`U256 → EXP → M256128 → M12850 → CE`。H的困难部件传到U的平均逐点梯度约1e-6，成功部件同样有约1e-7至1e-6；并非全部断梯度。EXP处梯度通常更大，但跨维度梯度范数的差异不能直接认定为故障。该探针只追到U，没有测更早backbone。

困难部件到达U的径向分量可能很小，例如H rocket42；同时切向分量仍存在。必须区分径向投影限制与全部监督失效。

最终M的有效权重行模长：H bag4=.304、bag5=.990、rocket41=.925、rocket42=.325、rocket43=.234；成功对照cap6=.971、mug37=1.027。H0 rocket42=.824。模长小与漏检有关联，但本次未通过只修改模长来验证因果，也没有检验初始化替换。

分项参数梯度保留完整B*N分母。困难部件与其余点的贡献存在负夹角，不能因此断言总体更新必然损害该部件，也不能把增强小类的诊断批比例当成自然训练比例。

### 3. 冻结读出器

七类各抽12个互不重复物体，8个用于拟合、4个用于检查，共56/28物体。两种子4780/4781；每个模型在U256和V128上分别拟合无偏置线性/带偏置仿射读出器，Adam .01、400步、每步8192点、普通50类CE。仅按拟合数据每通道RMS缩放，不减均值；这保持无偏置线性分类器的可表示集合。

编码器全程eval并冻结，参数与BN缓冲hash不变。编码器此前已经见过这些trainval物体；物体划分仅隔离探针拟合，不属于独立未见对象测试。只使用七类且类别比例增强，不能将探针成绩当成全任务提升。

### 4. 实际优化器一步反事实

H复跑best e182，恢复原RSGD状态、动量、权重衰减和当时LR=.0029654626。对三批分别比较CE、CE+contr、CE+hier、CE+两项R，共12个临时副本一步更新。恢复checkpoint RNG和part/negative RNG，各条件part索引hash、负例及更新前输出完全相同。采用训练态前传；比较更新前后时固定该次前传产生的BN缓冲，并检查另一固定批。检查点文件和CPU原始state均未变。

## 下一步建议

优先检验读出与监督优化，保持H的backbone及正则位置。冻结探针已经证明“可读信息存在”，但没有证明CE尺度或初始化因果。129的`CE(5z)/5`与R开/关配对仍是候选完整训练，当前没有启动。

若继续做定位，应首先在同一冻结U/V、同一原头初始化上比较原双曲读出监督与尺度改变，记录困难部件margin、输出权重行和有效更新；避免把不同随机线性头的成功直接当作原M初始化错误的证据。验证后再决定完整训练配置。后续评价必须回到DGCNN Class目标和全16类表现。
